# 客户需求与商机判断

需求发现不是把产品功能问一遍，而是让客户用自己的事实说明为什么要改变、为什么现在改变。

## 带着假设进会，让客户讲现状

会前先研究客户业务、角色和已知信号，把可能的假设列出来，但不要把假设当结论。和客户约好议程和时间，大部分时间留给客户讲现状。

从场景问起，追问当前流程、频率、参与者、成本、风险和现有的替代办法。再确认期望结果、可量化差距、不改变的后果和触发期限。问题跟着客户的回答往下追，不机械背问卷。没有真实痛点，就主动判定不进商机。

## 按角色分路取证，两类证据互证

按受访角色和业务类型走不同的证据路径，别对所有人用同一份问卷：业务负责人重点问结果、频率和经济影响；一线使用者重点问实际步骤、例外情况和替代办法；技术负责人重点问集成、数据、可靠性和维护成本；采购、安全或合规角色重点问准入条件、评估材料和否决项。行业差异从客户自己讲的流程、监管和交付约束里提取，不预设固定的行业模型；同一个问题至少拿业务结果和实际流程两类证据互相印证，别把一个角色的看法当成整个组织的共识。

客户不肯说、回答前后矛盾或只是礼貌性感兴趣时，不要连环逼问去补齐表格：记下已确认的事实、未确认的影响和不进商机的原因，约一个对客户也有价值的验证动作。国内招投标、预算批复、信创、安全审查或集团决策链，只在客户材料里出现时才纳入，不硬套固定采购流程。

## 分开记事实与推断，直接给商机判定

摸清业务影响、关键指标、经济决策人、评估标准、决策与采购流程、内部支持者、竞争或自建方案。已确认事实、客户原话、销售推断和未知项要分开记。不得把礼貌性兴趣、参加演示或下载资料当成购买意向。

用户已经给出访谈原话或资格事实、要的是判断时，直接基于这些材料判定，不先解释路由、读取 Skill 或搜索公开资料。用户明确说“不要联网”时，不得调用网页搜索或读取工具。技能文件、参考资料或工具不可用时，用本页已载入的方法把能做的先做完；不得发送“让我修正路径”“重新读取技能”“正在查找文件”这类过程消息。全部内部工作做完后只发送一次最终答复，第一句直接写“已形成商机”“尚未形成商机”或“证据不足以判断”，并点出决定性缺口；内部方法、路径、错误和工具过程都不进答复。

## 复述价值假设，定下双方下一步

结束前向客户复述问题和价值假设，把双方各自要做的下一步、负责人和日期定下来。交付发现摘要、影响量化、资格缺口、风险、商机判断和下一步。访谈与摘要模板见[客户商机发现方法](references/method.md)。
