# 安全代码审查

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “安全审查这个文件下载接口，重点看路径穿越和跨租户。”
- “验证这次 SQL 注入修复是否覆盖排序字段和批量查询。”
- “从 webhook 输入追到命令执行，只有可触发问题才报告。”

本能力处理的是**具体代码版本中的可触发攻击路径**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 变更差异与相关调用链
- 部署配置和信任边界
- 身份、输入与敏感资产说明

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 从外部可控输入追踪到解析、校验、授权、存储和危险调用；涉及 OAuth 时先对当前实现做观测型测试：在隔离环境替换响应边界或导航函数，记录当前代码是否会接受 issuer、authorization endpoint、redirect URI、state 或 PKCE 的错误绑定，不能只测试一个尚未接入应用的理想校验器
2. 对 OAuth 当前实现与修复后实现分别建证据：当前实现须从已配置 issuer 读取或使用固定 discovery 文档，返回 issuer 精确相等、authorization_endpoint origin 位于服务端 allowlist、redirect_uri 与注册值精确匹配、state 一次性且 PKCE S256；修复后用 example.invalid 伪 discovery 的 issuer 替换、endpoint 替换、redirect 不匹配、state 重放和 PKCE plain 断言在导航前被拒绝
3. 建立攻击前提、触发路径、影响资产和现有防护的完整证据链；若只能证明前端会导航任意 HTTPS URL、但无法证明上游攻击者可控制响应，则报告“当前实现缺少本层绑定 + 上游可控性未验证”的条件性发现，不写已利用
4. 按影响与可利用性定严重度并映射最贴近的 CWE；只有外部可控且能到达导航才升级，高影响前提未证实时最高标条件中危；修复必须接入真实调用链并用同一负向测试复测，独立 harness 通过只能证明验收 oracle 正确

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 发现危险函数不等于存在漏洞，必须证明可控数据能到达
- 认证成功不代表具备资源级授权；开放重定向、OAuth issuer 混淆和服务端请求伪造必须按实际数据流分别判断
- 日志脱敏、错误返回、密钥轮换和代码路径修复分别给责任人与验证信号

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 威胁范围与信任边界
- 可利用发现与代码位置
- 攻击前提和影响
- 修复建议或补丁
- 安全回归测试

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 只在授权代码和测试环境验证
- 不生成可直接攻击真实目标的利用载荷
- 发现现存密钥只报告位置并建议轮换，不回显值
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕具体代码版本中的可触发攻击路径完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要变更差异与相关调用链、部署配置和信任边界、身份、输入与敏感资产说明中的一项；否则只能交付空白框架和最小补充清单。

超出范围：角色资源矩阵用系统权限与越权风险审查；LLM 工具注入用专门安全审查；普通变更正确性用变更风险审查。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
