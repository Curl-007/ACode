# 系统性能瓶颈定位

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “定位订单接口 P99 从 300 毫秒升到 2 秒的主导瓶颈。”
- “用堆快照验证定时任务内存持续增长的原因。”
- “比较缓存命中、数据库等待和外部接口耗时，设计单变量实验。”

本能力处理的是**特定版本、负载和环境下的性能退化**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 基线与当前指标
- 可重复请求或工作负载
- 追踪、剖析、查询与资源数据

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 没有现成指标时先复制最小 harness：固定提交与运行时；用虚构夹具注入可控单请求延迟；从规模 1 开始按 2 倍递增，直到达到预计生产上界、延迟预算或资源安全阈值，不把 0/1/5/20/50 当通用固定规模；每个点预热一次、至少采样五次，保存 JSONL 原始值、环境和随机种子
2. harness 同时跑基线与单变量候选，计算排序后的 P50/P95/P99、失败率、请求数与最大并发；算法级模拟必须明确只证明增长曲线，不证明生产容量
3. 真实环境可用时再记录浏览器 HAR/Performance trace、服务 request-id/Server-Timing 或 OpenTelemetry trace、CPU profile、堆快照和数据库等待；用同一关联标识分解端到端时间
4. 用 trace 或 profile 验证主导瓶颈；缺少真实 trace 时交付“候选瓶颈 + 合成实验 + 现场采集步骤”，不得写成生产根因或提升百分比

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 平均值不能替代 P95、P99 和尾部失败分布
- CPU 高或慢查询相关不等于它是主导根因
- 微基准收益必须在真实调用链和代表性数据上复验

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 基线与最小负载／复现条件
- HAR／trace／profile 的时间资源分解
- 瓶颈假设、反证与置信度
- 验证实验结果（环境可运行时）或现场采集步骤（受阻时）
- 优化优先级与回归门

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 压测默认只在隔离环境
- 不记录生产请求中的个人数据和令牌
- 没有实际测量不得声称性能提升百分比
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕特定版本、负载和环境下的性能退化完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要基线与当前指标、可重复请求或工作负载、追踪、剖析、查询与资源数据中的一项；否则只能交付空白框架和最小补充清单。

超出范围：数据库具体 SQL 优化可用 Postgres 最佳实践；功能故障走故障定位；实现优化需行为契约与测试保护。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
