# 重点商机赢单策略

赢单策略不是罗列对手弱点，而是改变客户的评估标准、补齐资格缺口，再定出一条能和客户共同执行的成交路径。

## 逐项核验事实卡，未知不打中等分

逐项检查商机的可量化结果、经济决策人、评估标准、决策流程、采购/法务/财务流程、痛点、内部支持者和竞争态势。每项标明为已证实、推断或未知，并写下验证动作。单线联系、下一步含糊、日期只有销售自己报的，都是高风险信号。

第一张事实卡原样保留用户给出的商机金额、阶段、客户角色、竞争对手、价格差、期限和正式流程状态；后续分析不能把金额弄丢，也不能把用户的陈述升级成独立核验过的事实。

关键信息大面积未知时，先给“当前不可承诺的赢单判断、价值最高的三项验证、继续投入条件”，不把空字段打成中等分。客户材料看不了或工具失败时，只基于已提供的事实做一个假设版，不用公开传闻去补预算、权力关系或竞品方案。

Skill 或参考资料不可用时，直接用本页已加载的方法，不搜索或修正内部路径，也不向用户说明读取动作。

## 画权力图，比客户在乎的结果

画出业务使用者、技术评估者、采购、法务、财务、信息安全和最终决策人各自的影响力与立场。设计多线联系，但不能绕开客户联系人硬去越级触达。

比的是客户真正关心的结果、实施风险和总成本，不是功能表。分清赢区、胶着区和输区；输区要选一条路：改变范围、引入伙伴、验证能力，或者及时退出。不得捏造竞争信息，也不得贬损对手。

涉及招投标、信创、安全评审和预算审批时，把本次招标文件和客户流程读一遍，分清哪些是正式要求、哪些是评分项、哪些只是销售推断；不得设计围标、虚假资质、利益输送或绕过采购的策略。

## 共订实施计划，一次给出交易判断

和客户一起定共同实施计划，从验证、方案、商务、合同、采购、上线一直到价值确认，每一步都有双方负责人、日期和完成证据。交付商机评分、权力图、竞争策略、行动计划、风险和退出条件。正文只留判断和行动原则；真要出表时，读取[竞争交易策略方法](references/method.md)中的可填写交付卡，不另造字段。

取数、制表和校验全部做完后只发送一次最终答复，第一句必须以“交易判断：”开头；“我来阅读”“让我查看”“路径错误”这类过程消息禁止出现。
