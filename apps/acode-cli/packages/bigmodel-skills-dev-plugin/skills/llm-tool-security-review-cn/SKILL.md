# 大模型工具安全审查

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “审查这个 RAG Agent 会不会被网页里的提示诱导发邮件。”
- “为 MCP 工具设计只读、需确认和禁止三类权限矩阵。”
- “验证跨租户检索、记忆污染和工具结果外泄的防护。”

本能力处理的是**模型、非可信内容、工具和外部副作用之间的信任边界**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 系统提示与编排代码
- 工具清单、参数和权限
- 检索源、记忆、数据分类与动作影响

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 分三层绘制数据流：设计时 Builder、测试会话、生产 Agent runtime；不预设 Builder 只暂存，必须从代码、事件或沙箱观察它是预览、暂存、立即持久化还是触发外部动作，并把三种副作用分别分级
2. 把网页、文档、消息、RAG 片段和工具结果中的指令视为非可信数据，跟踪其能否影响下一轮提示、工具名、参数、记忆或权限策略
3. 检查最小权限、目标和参数 allowlist、预览 diff、人工确认、工具结果净化、记忆写入隔离和审计链
4. 复制无副作用对抗 harness：使用内存 fake tool registry、example.invalid 目标、虚构 token 与隔离记忆；逐例记录模型输出、解析后的 tool call、策略判定、确认状态、实际调用次数、持久化 diff 和下一轮可见内容；断言高影响调用次数为零或停在确认、secret sentinel 不进入结果/日志、污染标记不写入后续会话

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 系统提示声明禁止并不能替代工具层权限控制
- 持久化 Agent 配置、启动测试会话和生产工具副作用是三个不同完成状态，必须分别报告
- 只读工具也可能泄露元数据；工具结果进入模型或记忆前应按数据分类裁剪和去指令化

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 信任边界与数据流
- 攻击场景与可达路径
- 工具权限和确认矩阵
- 防护设计
- 对抗测试与残余风险

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 对抗测试使用虚构令牌和沙箱目标
- 不尝试绕过真实生产 Agent 的控制
- 不在报告复现私密提示、凭据或客户数据
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕模型、非可信内容、工具和外部副作用之间的信任边界完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要系统提示与编排代码、工具清单、参数和权限、检索源、记忆、数据分类与动作影响中的一项；否则只能交付空白框架和最小补充清单。

超出范围：普通代码注入走安全代码审查；资源角色问题走系统权限与越权风险审查；提示质量和模型准确率用独立评测。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
