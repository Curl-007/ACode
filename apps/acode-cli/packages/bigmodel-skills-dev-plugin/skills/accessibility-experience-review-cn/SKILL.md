# 网页无障碍检查与修复

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “只用键盘验收登录弹窗，检查焦点进入、关闭和返回位置。”
- “审查结算表单的语义、错误关联和动态提示。”
- “测量这组按钮与正文的对比度，并按用户影响给修复优先级。”

本能力处理的是**关键用户任务的可感知、可操作与可理解程度**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 页面地址或组件源码
- 关键任务和目标用户
- 浏览器、键盘与可用辅助技术

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 检查地标、标题、列表、表格、表单和控件的原生语义，并把发现映射到适用的 WCAG 2.2 成功准则
2. 只用键盘完成打开、输入、提交、取消和返回；逐步记录动作、活动元素、可见焦点、预期去向和实际去向
3. 验证错误、加载、成功和选中状态不只依赖颜色或图形
4. 用相对亮度公式计算 (L1+0.05)/(L2+0.05)：普通文字至少 4.5:1，大字至少 3:1，非文本控件和焦点指示至少 3:1；在 200% 与 400% 放大环境复走关键流程

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 自动扫描零问题不等于人工流程通过
- 没有运行目标读屏时不得声称读屏通过；占位符不能替代持久可见或程序化关联的输入名称
- 修复优先级先看是否阻断任务，再看误操作和理解成本；国内项目另列适用国标核对项，不把 WCAG 等级直接写成国内合规

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 环境、辅助技术与流程范围
- 用户影响、WCAG 条款与严重度
- 位置、复现与焦点轨迹证据
- 修复建议或补丁
- 键盘、缩放、对比度与读屏人工复测结果

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 生产提交与删除必须先授权
- 使用最小权限测试账号和虚构数据
- 报告不保存密码、验证码、令牌或个人资料
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕关键用户任务的可感知、可操作与可理解程度完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要页面地址或组件源码、关键任务和目标用户、浏览器、键盘与可用辅助技术中的一项；否则只能交付空白框架和最小补充清单。

超出范围：只修布局用响应式适配；业务状态实现走交互状态技能；一般浏览器回归走旅程验收。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
