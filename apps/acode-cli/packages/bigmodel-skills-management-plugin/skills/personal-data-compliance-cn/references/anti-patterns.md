# 个人信息合规审查领域反模式

## 一眼判为不合格的做法

- 不只审隐私政策文字而忽略真实系统
- 不把笼统同意当作所有处理依据
- 不凭记忆填写跨境数量门槛
- 不在报告中保留不必要的真实个人信息

## 如何修回可交付状态

| 错误做法 | 为什么失败 | 正确做法 |
|---|---|---|
| 缺少确认产品、用户、地区、主体角色和业务目的仍给确定结论 | 处理活动和主体角色失去事实基础 | 保留已知事实，把受影响字段标为待确认并列最小补充项 |
| 只交付处理活动和主体角色，不提供字段、目的和合法性基础 | 结果无法复核或交接 | 按输出契约补齐字段、证据状态和未覆盖项 |
| 未验证就声称“数据清单与真实系统流程一致” | 把目标冒充实际结果 | 执行对应检查并保留证据；不能执行时标为受阻 |
| 只审隐私政策文字而忽略真实系统 | 直接违反本技能的核心判断边界 | 停止该路径，回到按处理目的梳理收集、使用、存储、共享、委托、公开、跨境和删除并记录修订理由 |
