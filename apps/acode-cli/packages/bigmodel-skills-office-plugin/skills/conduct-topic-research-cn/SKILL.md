# 深度专题研究

先回答真正的研究问题，再决定报告目录。篇幅、图表和引用数量都不能代替证据覆盖。

## 建立问题树和证据计划

把主题拆成现状、机制、参与者、规模、变化、争议和影响等可验证问题。每个问题写明需要的一手证据、辅助证据、时间范围和停止条件；不要把搜索关键词列表当研究框架。

主题过宽时先交付一页研究任务书：决策用途、地区、时间、五个以内核心问题、明确不研究什么和第一轮证据计划；再列最多三个确认项（答案会显著改变范围的那种），不要停下来干等回复。研究计划默认保持紧凑：每个核心问题只保留一个决定性问题和所需证据；来源、冲突规则和停止条件各自归并，每类不超过四组；不把所有可能的分支展开成百科目录。用户没要详细报告时，优先用一页表格交付，不在正文后再重复要点。

优先使用政府、监管、统计、交易所、企业公告、标准、论文和原始数据。媒体和研究机构用来找线索、补背景；自媒体只能当观点，或当进一步核验的入口。涉及中国市场时覆盖中文正式来源，不能只引用海外二手报道。

## 研究到证据饱和

读取本 Skill 后直接执行，无需再读取其他方法文件。用户没有提供附件时不检查上传目录；没有要求文件时不创建、不保存，也不声称已生成文件。读取技能、参考材料、搜索结果和来源原文等步骤之间只做内部操作，不输出“好的”“我先”“让我”“已读取”“搜索结果已返回”等过渡句。完成取证和综合后只交付一次完整结果；正文结束后不得另起一条消息复述“以上内容”或再次总结同一结论。

重要结论要找独立来源，分清是相互印证还是相互转载。记录发布日期、事实发生日、适用地区、样本和口径。来源冲突就把冲突摆出来，从定义、时间、样本和利益关系解释差异；不能什么都不说明，就只挑自己偏好的数字用。

新增来源只是在重复既有事实、核心反例查过了、关键缺口也写清了，就停止扩展。缺数据不等于可以拿估算填空；确实要估算，就给出公式、假设和区间。

任务只要求核验一个当前名称、页面事实或企业信号时，不启动完整专题扩搜：拿到一条能直接读取、和声明对得上的官方原文就停，只在出现冲突或页面不可读时才引入第二来源。不得因为还能搜索就继续扩大范围直到超时。

搜索、网页读取或付费来源不可用时，记录失败来源与覆盖缺口，转用其他独立正式来源；所有来源都取不到时，只交付研究计划和已有材料的综合，不编造链接。任何失败返回都只代表“来源内容未取得”，不得引用、翻译、概括或解释失败返回本身。若任务是发现官网候选入口且一条候选 URL 都未取得，固定写成“研究结论：证据不足。当前未取得可核验的官网候选入口，因此没有 URL 可列，尚未完成原文核验；来源恢复可访问后重试。”面向用户不暴露内部工具名称，且不得出现“工具”“调用”“搜索失败”“读取失败”、内部服务名称、服务余额、资源包、错误码、HTTP 状态或调用次数。发送前若草稿含这些词，删掉失败解释，改为说明缺了哪个业务来源、对结论有什么影响。研究材料若含个人信息，只保留公开职业事实或任务必需的脱敏字段，不扩散私人联系方式和敏感画像。

## 综合而非堆砌

先写结论和证据强度，再写支撑事实、反例与限制。事实、来源中的观点和研究者推断分别标记。每项建议写明由哪条发现推出、在什么条件下会失效。

执行顺序：锁定任务书与问题树；为每题列一手来源和反例搜索；记录来源与口径；检查冲突、转载链和空白；达到停止条件后综合。对每个研究问题记录重要性、所需证据、已取得来源、反例、证据强度和未解决缺口。证据表字段为：问题、声明、来源标题/主体、链接、发布日、事实日、地区、样本/口径、证据等级、支持/反对、摘录、访问日和限制。

最终交付研究问题、执行摘要、主题分析、证据表、争议与空白、引用和更新时间。简单任务只交付核心问题、结论、三到五条关键证据和限制。访问日取本次运行环境的当前日期；来源页面上的发布日期、版权年份或数据期不能冒充访问日。发送前检查：第一行必须以“研究结论：”开始；全文只出现一份结论和一份总结；若存在英文引导句、背景说明、过程文字或结尾重复总结，删除后再交付。
