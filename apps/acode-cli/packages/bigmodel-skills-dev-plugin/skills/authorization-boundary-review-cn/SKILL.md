# 系统权限与越权风险审查

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “审查订单导出是否可能让普通成员看到其他部门数据。”
- “为项目空间设计角色、对象、动作和数据范围授权矩阵。”
- “验证批量更新接口的跨租户与间接对象引用防护。”

本能力处理的是**系统的资源级访问控制与租户隔离边界**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 角色、资源和业务规则
- 服务端路由与数据访问代码
- 租户、委托和管理员场景

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 先走部署决策树：若监听地址强制 loopback、无反向代理/隧道且只服务单一设备主体，按 local-only 建模；只要可绑定非 loopback、存在容器 Service/Ingress/反代/隧道或服务多用户，按 deployable-service 建模并要求部署清单、实际监听、代理认证、可信头配置、网络策略和共享 key scope 证据
2. local-only 仍检查本机恶意网页、CSRF 与其他本地进程边界；deployable-service 必须列主体、资源、动作、租户、数据范围和默认拒绝规则，从入口追踪服务端鉴权到查询过滤
3. 覆盖横向、纵向、跨租户、批量接口、导出和间接引用场景
4. 生成允许拒绝矩阵与负向测试；缺部署证据时只能写条件性严重度，本层无校验与上游未验证分别报告

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 前端隐藏按钮不能作为授权控制
- 角色允许某动作仍需检查具体资源与租户范围
- 超级管理员、服务账号和委托访问必须有独立边界和审计

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 授权模型与默认规则
- 主体资源动作矩阵
- 越权路径与证据
- 服务端修复点
- 负向测试与审计要求

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 不使用他人真实账号测试越权
- 测试采用隔离租户和虚构对象
- 不输出会话令牌、权限缓存或个人数据
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕系统的资源级访问控制与租户隔离边界完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要角色、资源和业务规则、服务端路由与数据访问代码、租户、委托和管理员场景中的一项；否则只能交付空白框架和最小补充清单。

超出范围：认证流程不在本技能范围；输入注入等漏洞用安全代码审查；个人信息处理合法性用数据合规能力。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
