# 代码库结构与运行指南

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “我明天接手这个仓库，画出请求入口、核心模块、数据库和测试路径。”
- “找出订单导出的真实入口和首次安全修改要跑哪些命令。”
- “只读分析这个 monorepo，区分生成代码、共享包和部署单元。”

本能力处理的是**一个有明确版本的代码库及其运行边界**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 仓库路径与当前提交
- 目标业务能力或接手范围
- 允许执行的只读命令

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 先读仓库说明、约束文件、包管理和工作区声明；JavaScript/TypeScript 追 package.json、锁文件、tsconfig 与构建器，Python 追 pyproject、锁文件与包入口，Java 追 Maven/Gradle 模块，Go 追 go.mod 与 cmd，Rust 追 Cargo workspace
2. 从进程启动入口、路由或命令入口沿导入和调用关系追到业务模块、数据访问、队列与外部依赖
3. 从测试配置、文件命名、夹具和流水线命令建立单元、集成、端到端与发布验证地图，并实际运行一个不改变状态的最小探测
4. 标出生成目录、供应商依赖、密钥边界、通配代理、数据写入、扩展点、所有者线索和首次改动验证路径

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 文件名只能形成假设，真实入口须由引用关系、脚本解析或运行证据确认
- 生成文件、缓存、构建产物和供应商目录不得当作核心源码
- monorepo 必须区分工作区边界、共享契约、部署单元和根命令的实际作用范围

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 仓库版本与范围
- 入口到依赖地图
- 构建测试命令表
- 修改热点与危险区
- 首次任务建议

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 默认不安装依赖、不启动外部服务、不修改源码
- 不读取或输出环境密钥
- 不把所有权猜测写成事实
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕一个有明确版本的代码库及其运行边界完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要仓库路径与当前提交、目标业务能力或接手范围、允许执行的只读命令中的一项；否则只能交付空白框架和最小补充清单。

超出范围：具体代码风险用变更审查；线上症状用故障定位；真正实现功能用行为契约实现。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
