# 数据清洗与变更追踪

目标不是把表格“弄整齐”，而是得到一份能重复生成、能解释差异、不会悄悄丢数据的分析副本。原文件保持只读；任何删除、替换、填补和合并都留下记录。

## 快速开始

提供只读原文件、行粒度、关键合计和清洗目标。可以复制：

- “清洗这份中国区订单明细，保留原件，输出变更表、异常明细和金额对账。”
- “先预览手机号脱敏、日期标准化和业务键去重分别会影响多少行，不要直接执行。”
- “合并客户表与订单表，检查一对多放大，并给我可复跑脚本和文件摘要。”

## 受众

- 数据分析与运营人员：获得可分析副本和口径清楚的变更表。
- 数据工程与测试人员：复跑规则、核对依赖和验证前后差异。
- 业务负责人及合规人员：审批会改变金额、记录数或个人权益的规则。

## 能力边界

- 擅长：处理缺失、重复、类型、日期、单位、异常和跨表匹配，并为每一处变化建立可复算血缘。
- 需要素材或授权：至少需要只读数据、字段说明、业务键或清洗目标中的一项；生产写回、删除记录和处理完整个人信息必须明确授权。
- 超出范围：首次理解陌生数据转给数据摸底；统计推断、预测和经营结论用相应分析能力；本技能不替业务定义未知规则。

## 缺项、异常与降级

缺少关键口径时使用：

> 需要补充以下 N 项才能完成：缺少什么；会影响哪条规则或对账；最小补充方式。当前已完成：只读画像和规则预览。待确认：会改变记录、金额或用户权益的动作。

文件打不开、依赖不可用或数据量超限时，保存失败位置与已读取范围，交付离线规则和复跑命令，状态写“受阻”或“未执行”；不得把样例输出写成真实结果。未验证内容不能写成已完成。

## 定制参数与增值能力

可传入目标受众、输出篇幅、格式、口吻、时区、币种、空值定义、风险阈值、业务键、保留优先级和允许动作。默认主动识别多对多放大、跨期口径漂移和不可逆规则，按金额与记录影响排序，并为高风险规则生成撤销路径和抽样复核清单。

## 安全、隐私与禁止行为

- 适配中国企业常见订单、客户、门店、人民币与北京时间数据，但实际字段含义以用户材料为准。
- 个人信息、商业秘密和凭证遵循最小必要；分析副本删除或脱敏手机号、证件号、银行卡号、精确地址和密钥。
- 禁止覆盖原文件、静默删除、选择性清洗、绕过审批或伪造命中数量；生产写回必须展示差异并由授权人员批准。

## 开始前准备三样东西

- 原始文件的只读副本，以及文件名、行数、字段数和关键合计；
- 业务方确认的行粒度、去重字段、合法范围和不可删除记录；
- 每行稳定编号。原表没有编号时，在副本中新增来源文件与原行号组合，不用姓名或手机号当编号。

缺少业务定义时，先生成问题清单和清洗预览。会改变记录数、金额或用户权益的规则不得直接执行。

## 用变更表驱动清洗

每条规则先写入变更表，再运行。至少包含：规则编号、目标字段、判断条件、处理动作、原因、命中行数、示例行号、是否改变记录数、是否可撤销、执行时间和代码位置。

推荐顺序：

1. 统一字符编码、首尾空格、空值表示和字段类型；解析失败单独保存。
2. 统一日期、时区、币种、金额与百分比单位；保留转换前值或可重建方法。
3. 分开识别完全重复、业务键重复和业务允许的多条明细。
4. 将缺失分成未知、不适用、未采集与系统错误；按用途决定保留、排除或填补。
5. 用业务范围和分布发现异常；无法判断的记录加标记，不凭直觉删除。
6. 合并表格前检查连接字段是否唯一，合并后计算匹配、未匹配和一对多增加的行数。
7. 输出分析副本、异常明细和变更表，不覆盖原文件。

## 三类高风险处理

### 去重

明确保留规则，例如“同一订单号优先保留更新时间最新且状态完整的一条”。报告重复组数、涉及行数、保留行数和删除行数。若金额或状态冲突，先列冲突记录，不自动挑选。

### 缺失填补

只有填补不会改变字段含义且方法可解释时才执行。报告原缺失数、填补数、仍缺失数和填补方法。均值填补会压低波动，时间序列前向填充会假设状态持续，这些影响必须写明。业务语义不明确时保留缺失。

### 异常值

统计阈值只是线索。先判断是录入错误、单位错误、真实极端事件还是未知。删除或缩尾前分别计算“保留异常”和“处理异常”两版关键结果，结论改变时必须升级为待业务确认。

## 前后对账公式

- 行数：输入行数 = 保留行数 + 删除行数；新增行必须有明确生成规则。
- 主体数：清洗前后分别按确认业务键去重计数。
- 金额：输入有效金额合计、输出金额合计、差额；差额应能由删除、修正和新增记录逐项解释。
- 连接：左表行数 + 一对多增加行数 = 连接后行数；同时报告未匹配键数。
- 缺失：原缺失数 = 已填补数 + 仍缺失数 + 因删除记录减少的缺失数。

涉及比例时保留分子、分母与四舍五入规则。同一输入和同一规则重复运行应得到相同输出。

## 交付顺序

1. **清洗结果**：输出位置、输入/输出行列数、关键合计和可分析范围。
2. **变更表**：逐规则记录实际命中数量，不用“已处理”替代数字。
3. **未处理问题**：冲突、解析失败、无法匹配和需业务确认记录。
4. **复跑方法**：公式、查询或代码、依赖版本、运行命令与输入位置。
5. **对账结果**：逐项解释行数、主体数和金额差异。

不得伪造命中数量或声称未运行的脚本已经成功。受限环境中可以交付规则草案和预览，状态写“未执行”。敏感字段在分析副本中删除或掩码，不保留可重新识别个人的映射。

## 清洗答疑

1. **能把所有空值填零吗？** 不能；零必须表示真实业务数量为零。
2. **发现离群值就删除吗？** 不删除，先查原因并做有无该记录的结果对比。
3. **可以直接改原表吗？** 不可以，输出新副本并保留复跑方法。
4. **订单号重复就是脏数据吗？** 不一定，订单明细表本来可能一单多行。
5. **合并后金额翻倍怎么办？** 检查连接字段唯一性和一对多关系，撤销合并后修正规则。
6. **规则变了怎么办？** 新增版本和原因，用同一输入重跑并比较差异。
