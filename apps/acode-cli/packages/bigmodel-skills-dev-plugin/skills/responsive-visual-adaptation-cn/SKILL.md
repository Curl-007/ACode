# 多端页面视觉适配

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “修复订单表格在 860 像素开始横向撑破页面的问题。”
- “用长中文标题、缺图和 200% 缩放检查这个卡片列表。”
- “按现有设计变量完成手机到桌面的布局适配并给截图证据。”

本能力处理的是**页面在内容与视口压力下的视觉稳定性**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 可运行页面或样式源码
- 设计稿与项目设计变量
- 目标浏览器、宽度和内容样本

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 用 320、360、390、768、1024、1280 像素起始矩阵逐步拖动容器，并在每个组件首次溢出、遮挡或操作换行的前后各记录一个压力点；百分之二百缩放必须用真实浏览器缩放，等效窄视口只能标代理
2. 为各区域选择流动、换行、重排、折叠或局部滚动策略
3. 复用字号、间距、颜色、圆角与容器等既有变量
4. 用长中文、连续数字或网址、缺图、单项与大量列表做回归；记录 viewport、zoom、DPR、scrollWidth/clientWidth、控件包围盒和截图编号

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 断点由内容失效点决定，不按设备型号机械堆叠
- 图片必须明确完整展示或裁切填充及主体对齐
- 窄屏修复不得靠隐藏主要操作或改变阅读顺序

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 视口／缩放／内容压力记录
- 区域适配策略
- 复用或变更的设计变量
- 截图编号与 scrollWidth／包围盒测量证据
- 未覆盖环境

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 不擅改业务逻辑
- 不下载来源不明字体、图片或前端包
- 截图与夹具移除客户姓名、手机号和账号标识
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕页面在内容与视口压力下的视觉稳定性完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要可运行页面或样式源码、设计稿与项目设计变量、目标浏览器、宽度和内容样本中的一项；否则只能交付空白框架和最小补充清单。

超出范围：交互错误交给页面状态实现；键盘与语义问题交给无障碍审查；端到端行为由浏览器验收。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
