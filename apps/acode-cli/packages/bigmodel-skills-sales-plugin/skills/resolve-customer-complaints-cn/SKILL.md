# 客户投诉处理

投诉不是“更生气的工单”。客户通常同时要四样：把事实说清、马上止损、处理公平、被认真对待；四件事要分别回应。

## 先控制二次伤害

把会话完整读一遍，确认客户的明确诉求、实际损失、已承诺事项、重复沟通次数和紧迫节点。能确认的体验问题和影响，先认下来；事实没弄清之前不抢先认定法律责任，也不要拿“给您带来不便敬请谅解”顶替具体回应。

事实或诉求还不齐时，先确认看得见的影响、止住还在发生的损害，说清临时负责人和下次更新时间；追问只限会改变权益或补救方案的最少信息。投诉材料按最小权限访问，对外回复和内部记录都要脱敏，验证码、完整证件、银行卡和无关聊天内容不得复制留存。

客户情绪激烈、不肯补充信息或暂时没法继续沟通时，不要反复追问，也不要用关闭工单施压。先复述已确认的损失和诉求，把不需要客户配合的止损先做掉，明确专属负责人、下一次主动更新时间和恢复沟通的渠道；缺的事实标成待确认，不能因为缺就拒绝基本权益或编造结论。出现威胁、自伤、人身安全或重大财产风险，按组织应急规则立即升级，不让一线人员独自处置。

如果还在扣费、停服、泄露、误发或持续延误，先做授权范围内的止损。暂停、退款、补偿、恢复服务、删除数据和公开回应都可能改变外部状态；必须核对权限、金额、对象和不可逆影响，超出权限就提交审批，不要口头承诺。

## 把争议拆成四张卡

**事实卡**：时间线、订单或服务、客户证据、系统记录、已确认与待确认事实。

**权益卡**：适用合同、平台规则、售后政策、消保要求和历史承诺。不能只引用对公司有利的条款。

**补救卡**：客户想要什么，公司能做什么，立即措施、最终方案、完成时间和验证方式。

**关系卡**：客户价值、流失或舆情风险、沟通渠道、负责人和后续关怀；不能按客户价值决定要不要履行基本权益。

## 给出有权限的处理方案

方案先把客户应得的状态恢复回来，再谈额外的安抚性补偿。退款或补偿写清金额、路径、到账区间、税票或优惠券影响和批准状态。有多种方案时，说明每种解决什么、客户需要做什么，不得用“二选一”施压逼客户放弃法定权益。

对外回复依次写：对客户诉求的理解、已确认事实、正在采取的动作、解决方案、时间点、负责人和再次升级入口。内部记录保留责任讨论、政策依据、审批和风险，这些不要原样发给客户。

用户要求直接回复客户时，只输出可直接发送的客户正文，不加“以下回复”“客户回复”“结构说明”，也不加自己是否遵守规则的自检说明。没有系统回执、工单号、批准记录或到账凭证时，正文不得出现“已提交、已升级、已退款、已补偿”这类完成态词语，就算是否定这些词也不要写；改成“当前尚未确认重复扣款，需由有权限的团队核对订单与支付流水后决定补救方案”。

不得在客户正文后接着生成第二版、内部自检表、文件或“内部交接记录”，除非用户明确要这些东西。未要求文件时禁止创建或宣称保存文件。生成正文前后都不发过程消息；最终只能有一条客户答复。

关闭投诉前确认四件事：客户核心诉求处理了没有、承诺兑现了没有、工单状态对不对、同类问题要不要批量排查。客户不同意方案不等于可以关闭；把分歧和还能继续用的渠道记下来。

投诉分级、权限把关和回复检查见[投诉处置决策表](references/method.md)。把四张卡对应到企业现有的工单字段、审批角色、服务时限和升级队列；字段叫法不同没关系，保留业务含义即可，不预设具体厂商。参考资料或工单系统用不了时，照样按四张卡做手工交接，不口头承诺系统动作。
