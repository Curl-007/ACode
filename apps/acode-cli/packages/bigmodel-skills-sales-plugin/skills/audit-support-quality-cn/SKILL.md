# 客服会话质检

客服质检要回答“系统为什么反复制造同类问题”，不能只给坐席打分。

## 设计可信样本

先定好审计期间、渠道、队列、语言、客户层级和问题类型。随机样本拿来估整体质量，风险样本拿来抓严重问题，两边分开报告；不能拿投诉样本去推断所有会话的满意度。

总量、抽样规则、有效样本和排除原因都要留底。机器人转人工、重复咨询、超长会话、低满意度和退款会话可以单列专项层，但替代不了基础随机样本。

渠道有缺、身份关联不上或时间窗口不完整时，把测得了的指标和测不了的偏差分开报告，不能把结果未知的会话当成已解决。自动质检、导出或知识库用不了时，就用可追溯的人工抽样表做最低限度的审计，写明覆盖率和截止时间。

Skill、参考资料或文件路径不可用时，直接按本页已加载的方法继续做；不得搜索替代路径，不得向用户播报读取、重试或“已掌握方法论”。内部检查做完，只发送一条最终审计方案或审计结果。

不要为了拿到方法文件反复列目录、改路径、读全文；本页已经包含完成质检方案的必要流程。参考文件第一次读不到，就立即停止所有文件尝试并静默降级。用户没要文件就直接在答复里交付，不创建计划文档。

## 从客户结果倒推质量

逐单检查五个维度：

- **正确**：事实、政策、账户状态和承诺有依据；
- **解决**：客户目标是否完成，而不只是客服发出了回复；
- **效率**：首次响应、有效响应、解决时间和不必要往返；
- **体验**：是否理解诉求、表达清楚、没有推诿或机械重复；
- **安全合规**：身份核验、敏感信息、授权动作和必要升级是否正确。

首次解决率必须看同一问题在约定窗口内有没有再次联系。满意度只覆盖有反馈的客户，代替不了整体解决率。从自动质检结论里抽出高风险和低置信度样本，交人工复核。

审计数据去掉不必要的姓名、联系方式、证件、支付信息和会话附件；原文谁能看，按角色和审计目的来限。涉及个人信息或跨境处理时，核对组织当前适用的分类分级、保存和访问规则，不自行下法律结论。

## 找到可修复的系统原因

把问题归因到知识缺失或过期、检索失败、产品缺陷、权限与流程、培训、排班容量、工具界面或激励指标。不要把“客服不认真”当成终点；接着追问是什么条件让错误容易发生。

输出质量基线、严重问题、问题聚类、影响量级和改进清单。每个改进必须落成一张行动卡：系统原因、动作、负责岗位、完成证据、验证指标、目标值、复查日期。材料里没给姓名，就写明有权推进的岗位，不得只写“指定负责人”；没给具体日期，就按审计周期给一个明确的建议日期并标为待确认，不得只写“下月”或“连续两周”。知识文章上线不算闭环；还要看重复咨询、解决率或错误率有没有改善。

抽样、评分与复查字段见[客服质量审计方法](references/method.md)。
