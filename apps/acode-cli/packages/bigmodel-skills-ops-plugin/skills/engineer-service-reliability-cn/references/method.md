# 服务可靠性设计

## SLO 卡

记录：用户旅程、好事件/总事件或连续值定义、测量点、窗口、目标、允许排除、数据负责人、当前基线和复查日期。排除规则必须在事故前定义。

错误预算为 `1 - SLO`。同时观察短窗口与长窗口消耗：短窗口快速消耗用于紧急响应，长窗口持续消耗用于限制高风险发布。恢复发布前要求预算消耗回到策略区间且触发问题已有保护。

## 容量与韧性情景

至少计算基准峰值、增长后峰值、单依赖退化和故障域损失。区分计算得到的吞吐实例数、部署高可用下限、维护余量和依赖配额；取约束中的最大值。

可靠性行动按用户影响、预算消耗、实施成本和风险降低排序。每项写预期改善的 SLI、验证实验、负责人和失效回退。国内云、跨地域灾备或数据驻留只有在项目实际使用时纳入，不预设供应商。
