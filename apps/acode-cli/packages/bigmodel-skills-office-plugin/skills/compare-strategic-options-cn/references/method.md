# 选项比较方法

## 评分表

每行使用以下字段：标准、硬约束、权重、测量口径、候选项 0～4 分、证据等级、未知项、验证动作。权重只用于软指标且合计为 1。

证据等级：A=相同条件下的一手测试或合同承诺；B=可核验正式资料；C=有方法说明的独立二手资料；D=销售说法或未经验证推断。D 级不能单独决定高风险选择。

总分为 `Σ(权重 × 分数)`。未知分数按 0～4 计算区间，而不是补 2 分。若候选项在合理未知区间内会反转排名，先验证最有决策价值的未知项。

脚本输入示例：

```json
{
  "options": ["自研", "采购"],
  "criteria": [
    {"name": "数据驻留", "hard_constraint": true, "scores": {"自研": true, "采购": false}},
    {"name": "三年总成本", "weight": 0.6, "scores": {"自研": 2, "采购": 4}},
    {"name": "上线速度", "weight": 0.4, "scores": {"自研": 1, "采购": null}}
  ]
}
```

`null` 表示未知。脚本只计算门槛和分数区间，不替代来源核验与风险判断。

## 敏感性与冲突

至少检查：最高权重上下浮动、关键成本区间、实施延期和一个风险事件。权重冲突时分别呈现主要利益相关方情景；不要把政治妥协伪装成数学唯一解。若情景给出不同首选，写明分歧方、各自目标、共同硬约束、会改变选择的阈值，以及拥有最终决策权的人和最晚决定日；没有决策权信息时保持条件式推荐。

若 A 成本更低但上线更慢、B 上线更快但数据风险更高，且两者都未被另一项全面支配，它们属于帕累托前沿。推荐必须绑定优先目标和改选条件，例如报价超过阈值、试点未达到性能、数据驻留无法满足或监管要求变化。

## 失败判断

- 硬约束被高总分抵消：评分模型无效，回到门槛筛选。
- 同一因素在多个指标重复计分：合并或重分权重。
- 来源口径不同：先统一测试或成本口径。
- 数据不足以排序：给条件式推荐和最小验证实验，不强排。

## 最小交付

简单二选一至少输出：硬约束结论、同口径对比、关键未知、当前条件式推荐、一个验证动作。复杂比较再增加完整评分、利益相关方情景、敏感性、帕累托前沿和改选条件。
