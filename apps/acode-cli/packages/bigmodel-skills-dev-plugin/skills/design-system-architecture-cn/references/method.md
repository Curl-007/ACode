# 系统架构决策方法

质量属性必须可验证，例如高分位延迟、可用性、恢复点与恢复时间、峰值规模和成本上限。组件图中的每条边说明协议、数据、超时、重试和责任方。

架构决策记录不写“采用最佳实践”。记录为何当前约束下选它、放弃什么、何时重审。容量估算保留公式和单位，并用监控验证假设。

## 最小交付物

- 上下文图：用户、外部系统、信任边界。
- 组件与数据所有权：每份核心数据只有明确主责方。
- 两条关键时序：正常路径和一个部分失败路径。
- 容量表：输入假设、公式、结果、余量、验证指标。
- 决策记录：选择、备选、取舍、风险、重审触发条件。
- 演进顺序：先上线什么、如何兼容、如何回退、何时删除过渡层。

图中的每个技术组件必须回答“它解决哪个已确认约束”；答不出来就删掉或降为备选。

容量表中的字节统一换算为 GiB（除以 `1024³`）或明确使用 GB（除以 `1000³`），不能混用。至少做一次独立验算并显示中间量，例如每日数据量；发现十倍、千倍差异时先检查单位、时间窗和峰均比。最终摘要必须与容量表逐项一致；摘要中的峰值、实例数或存储量与表格不一致即视为未完成估算。
