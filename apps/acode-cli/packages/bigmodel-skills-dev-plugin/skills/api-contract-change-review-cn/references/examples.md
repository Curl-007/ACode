# API 变更兼容性审查完整示例

## 示例一：材料完整

**用户请求**：“审查这次 OpenAPI diff，会不会破坏旧版移动端。”

**处理**：以下仅说明如何锁定有基线与候选版本的服务接口契约并组织契约语义差异表和消费者影响矩阵；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：新增必填字段和收窄枚举属于破坏性变化。



## 示例二：材料缺失

**用户请求**：“把 amount 从字符串改为整数，给兼容迁移和废弃观测方案。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 当前与拟议契约或代码差异；2. 已知消费者和发布顺序。当前已完成：契约语义差异表框架。待确认：状态码、空值和错误体变化可能比字段删除更危险。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线契约语义差异表。限制：不调用生产接口验证破坏性请求。下一步：在沙箱或获批环境补一次验证。
