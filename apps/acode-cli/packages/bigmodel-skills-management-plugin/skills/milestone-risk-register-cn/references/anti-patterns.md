# 项目里程碑与风险跟踪反模式

## 禁止用法

- 把已发生问题仍写成风险
- 只有风险描述没有触发条件和责任人
- 为了简洁覆盖历史状态
- 把“工具已配置”写成“工具已经返回结果”。
- 用样例数据、默认值或常识补齐真实业务状态。

## 错误与修复对照

| 错误做法 | 为什么失败 | 正确做法 |
|---|---|---|
| 把已发生问题仍写成风险 | 破坏事实、来源或口径的可追溯性 | 记录原始来源、日期、适用范围与证据状态 |
| 只有风险描述没有触发条件和责任人 | 导致关键对象、责任、时间或权限边界失真 | 最小化数据，并把缺失项和审批动作显式列出 |
| 为了简洁覆盖历史状态 | 造成越权、误判或错误行动 | 明确事实、推断和待确认，给出验证方法 |

## 发送前扫描

- 是否出现没有来源的具体数字、日期、姓名或系统状态？
- 是否把搜索摘要、会议建议或关联变更写成事实？
- 是否出现令牌、密码、完整证件号、完整手机号或私人联系方式？
- 是否包含未经授权的发送、写入、回滚、重启、删除或承诺？
