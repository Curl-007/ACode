# 大模型工具安全审查反模式

## 一、把线索当结论

错误：只看一个文件名、截图、日志末尾或单项指标就宣布根因或通过。

改进：围绕“模型、非可信内容、工具和外部副作用之间的信任边界”补齐来源、路径和反证；找不到直接证据时把结果降级为推断。

## 二、跳过核心判断

错误：忽略“系统提示声明禁止并不能替代工具层权限控制”，直接给通用最佳实践清单。

改进：先执行本技能工作流，再让每条建议对应一个可触发风险、具体位置与验证方法。

## 三、用成功措辞掩盖未运行

错误：没有执行命令、测试或现场复核，却写“已修复”“已通过”“性能提升”。

改进：明确区分已核验、用户提供、推断、受阻与未执行，给出现场复测条件。

## 四、越权扩大任务

错误：为方便验证而发布、删除、写生产、访问其他租户或输出凭据。

改进：对抗测试使用虚构令牌和沙箱目标；高影响动作停在草稿、预览或沙箱验证，并等待明确授权。

## 禁忌清单

- 对抗测试使用虚构令牌和沙箱目标
- 不尝试绕过真实生产 Agent 的控制
- 不在报告复现私密提示、凭据或客户数据
- 禁止把示例、模拟数据或记忆中的版本行为冒充当前环境事实。
- 禁止为凑报告数量重复同一发现，或把相邻能力的交付物改名后塞入本技能。
