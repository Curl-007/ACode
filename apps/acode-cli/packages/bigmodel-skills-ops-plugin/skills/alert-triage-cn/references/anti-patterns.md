# 系统告警分级与处置反模式

## 禁止用法

- 看到高延迟就直接判定数据库故障
- 告警合并后丢失关键区域差异
- 在无审批时直接重启或扩容
- 把“工具已配置”写成“工具已经返回结果”。
- 用样例数据、默认值或常识补齐真实业务状态。

## 错误与修复对照

| 错误做法 | 为什么失败 | 正确做法 |
|---|---|---|
| 看到高延迟就直接判定数据库故障 | 破坏事实、来源或口径的可追溯性 | 记录原始来源、日期、适用范围与证据状态 |
| 告警合并后丢失关键区域差异 | 导致关键对象、责任、时间或权限边界失真 | 最小化数据，并把缺失项和审批动作显式列出 |
| 在无审批时直接重启或扩容 | 造成越权、误判或错误行动 | 明确事实、推断和待确认，给出验证方法 |

## 发送前扫描

- 是否出现没有来源的具体数字、日期、姓名或系统状态？
- 是否把搜索摘要、会议建议或关联变更写成事实？
- 是否出现令牌、密码、完整证件号、完整手机号或私人联系方式？
- 是否包含未经授权的发送、写入、回滚、重启、删除或承诺？
