# 多项目优先级与资源分配

组合管理的核心就是做取舍。把所有项目都标成最高优先级，等于没有优先级。

## 给数据可信度分级

先把各项目的最小信息对齐：目标、战略关联、预期收益、合规或合同强制性、总成本、关键资源、时间窗口、依赖、风险、已投入和退出代价。数据可信度单独打分，不能拿精确的分数掩盖站不住脚的商业论证。

数据缺了，不能让项目自动拿到中间分：给收益、成本和期限分别标 A（有合同/实测）、B（有方法与负责人）、C（粗估）、D（仅有主张、无证据），再看未知项会不会改变投停决定。会改变的，先安排验证，或给出带条件的组合方案，不做伪精确排名。

## 先保强制项，再比增长

先保住真正的强制项目和运营底线，再去比增长、效率、降风险和能力建设。评分只辅助讨论；还要检查重复收益、项目间互斥、共同依赖和关键岗位瓶颈。

## 搭情景，算清停止代价

按基准以及预算收紧、增长优先或风险优先情景分别建模，列出各情景下启动、继续、降速、暂停和停止的项目，以及释放或占用的资源容量。沉没成本不能作为继续投入的理由；决定停一个项目，要同时处理合同、人员、数据和已交付资产。

## 把评审落成投停决定

组合看板只看收益兑现、资源容量、关键风险和决策，不汇总所有任务。每次评审都要落下明确的投停决定、附带条件和复查日期。评分与情景字段见[项目组合治理方法](references/method.md)。
