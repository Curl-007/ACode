# 大模型工具安全审查完整示例

## 示例一：材料完整

**用户请求**：“审查这个 RAG Agent 会不会被网页里的提示诱导发邮件。”

**处理**：以下仅说明如何锁定模型、非可信内容、工具和外部副作用之间的信任边界并组织信任边界与数据流和攻击场景与可达路径；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：系统提示声明禁止并不能替代工具层权限控制。



## 示例二：材料缺失

**用户请求**：“为 MCP 工具设计只读、需确认和禁止三类权限矩阵。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 系统提示与编排代码；2. 工具清单、参数和权限。当前已完成：信任边界与数据流框架。待确认：持久化 Agent 配置、启动测试会话和生产工具副作用是三个不同完成状态，必须分别报告。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线信任边界与数据流。限制：对抗测试使用虚构令牌和沙箱目标。下一步：在沙箱或获批环境补一次验证。
