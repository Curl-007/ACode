# 真实浏览器流程验收

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “在测试环境验收保存草稿流程，刷新后还要存在。”
- “复现支付页重复点击发出两次请求的问题并留网络证据。”
- “验证这次修复在桌面和手机视口的主流程与权限失败分支。”

本能力处理的是**指定构建版本上的真实浏览器用户旅程**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 网址或启动命令与构建标识
- 测试角色、初始数据和允许动作
- 浏览器、视口与预期结果

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 锁定版本、账号角色、初始数据、视口和清理范围
2. 按动作、页面反馈、网络请求和持久化结果走主流程
3. 覆盖风险最高的失败、权限、重复操作或刷新分支
4. 最小化失败步骤并保存时间、环境、预期和实际结果

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 前端成功提示但刷新后消失不能判定通过
- 环境不可用、产品失败与偶发测试问题必须分开
- 浏览器不可用时日志和录像只能支持受阻结论

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 验收环境锁
- 步骤级证据记录
- 通过失败受阻清单
- 最小复现
- 测试数据清理结果

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 生产环境默认只读
- 下单、发消息、提交和删除需明确授权
- 截图与网络记录遮盖 Cookie、令牌和个人数据
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕指定构建版本上的真实浏览器用户旅程完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要网址或启动命令与构建标识、测试角色、初始数据和允许动作、浏览器、视口与预期结果中的一项；否则只能交付空白框架和最小补充清单。

超出范围：需求设计不清先建立前端契约；代码修复走交互状态；视觉或无障碍专项使用对应能力。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
