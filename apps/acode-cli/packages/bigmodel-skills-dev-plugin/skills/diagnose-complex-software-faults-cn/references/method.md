# 复杂故障诊断方法

每个实验只改变一个主要变量，并提前写预期结果。观测与假设不一致时更新假设，不把反证强行解释过去。连续实验信息增益低时停止，补可观测性或缩小样本。

根因连接“触发条件 → 内部缺陷 → 可观测症状”，并解释为何不是其他候选原因。

## 假设表

| 假设 | 已解释事实 | 解释不了的事实 | 区分实验 | 支持时看到 | 反证时看到 |
|---|---|---|---|---|---|

不要按熟悉程度给假设排序；先按它能否解释异常与正常样本之间的差异排序。生产实验优先选择只读、低负载、可撤销方式，不能为定位问题扩大用户影响。

如果当前证据只能定位到组件或时间窗，结论写“已缩小范围”，不能把相关性升级为根因。

## 根因到修复的交接

诊断完成后输出：已确认因果链、仍被排除的相近原因、最小代码边界、修复前必失败用例、修复后主信号、数据/兼容回归、回滚触发和稳定观察窗口。代码实现由交付变更流程承接；诊断阶段不得把“建议加锁/关闭重试/清缓存”写成已完成修复。
