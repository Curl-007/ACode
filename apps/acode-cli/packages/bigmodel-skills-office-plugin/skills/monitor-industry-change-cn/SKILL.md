# 行业动态追踪

追踪的价值在于回答“跟上次比，什么真的变了”，不是把近期链接再汇总一遍。

## 建立可比较基线

记录主题范围、关键主体、指标、已知状态、监测频率、地区和上次截止时间。为法规公告、产品发布、价格、融资、人员、诉讼、招投标、专利或舆情分别选择合适来源；来源清单里写明访问失败与未覆盖来源，不能把空白当成没有变化。

用户没给范围或频率时，先按给出的主题建一个窄基线，按变化快慢暂定日报、周报或月报；频率和纳入/排除项标为待确认。工具不可用时保留上次基线、失败来源和待补窗口，不把“未检索到”写成“没有变化”。

事件日期、公告日期和媒体报道日期分开保存。更新旧事件时改状态、留版本，同一事件的十篇转载不能算成十个变化。

## 判断变化强度

把新信息分为确认变化、早期信号、重复信息和更正。确认变化要有原始或可靠证据；早期信号要写清还缺哪一步验证。再看这个变化动了哪条基线、影响谁、影响什么时候显现、要不要行动。

按影响范围、不可逆性、发生概率、响应窗口和证据强度排序；政策的征求意见、正式发布和生效，必须分开对待。

预警级别看当前组织的响应时限和影响条件，不采用跨行业固定百分比。立即响应，要有已触发的硬约束或很短的响应窗口；准备响应，要有可靠信号且可能在计划期内触发；证据还不完整或窗口较长的，持续观察；不改变当前决策的事实，仅记录。

只突出新增、升级、降级和被推翻的事项。每项包含变化、证据、影响、下一观察点。没有重大变化就如实报告，并说明哪些来源没覆盖到。简报字段见[主题变化监测协议](references/method.md)。

输入同时给了基线快照和当前快照时，直接逐字段比较，不要转去做静态选项比较。最终答复第一行必须以“变化判断：”开始；新增、修改、未变化和未知分别列出，不能用“比较结论：”替代。
