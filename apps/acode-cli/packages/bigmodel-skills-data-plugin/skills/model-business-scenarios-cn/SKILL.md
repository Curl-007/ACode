# 业务预测与方案测算

用少数几个解释得通的业务驱动，把假设和结果连起来，让决策者看到什么必须成立、结果对什么最敏感、什么时候该换方案。不要用一个精确数字掩盖不确定性。

## 建立驱动模型

先写结果等式，再决定要多少历史数据。比如收入由客户数、转化、频次和单价驱动；客服容量由请求量、处理时长、可用工时和利用率驱动。驱动必须能理解、能观察或能干预，不拿时间序列的拟合项冒充业务原因。

输入不完整时，先给出“结果、时间粒度、驱动、约束、实际/假设/估计”参数表和空白公式，手头已有的数字先做一轮可复算的局部测算。计算环境不可用时，简单等式就手算；复杂模型只交付公式和运行要求，不伪造输出。

输入分三类：实际值、用户确认的假设、由历史数据估计的参数。每个估计都写明样本期间、方法和局限。遇到季节、活动、价格变更或结构变化，要单独建模，不要用简单平均抹平。

## 选择适合问题的预测方式

数据少、业务结构清楚时，优先驱动模型；历史稳定、需要的是短期基线时，用时间序列；新业务没有历史时，用可类比业务的参考区间加显式假设。复杂模型只有在留出验证上稳定赢过简单基线时才用。

按时间顺序划分训练与验证，不能随机打乱，免得未来信息混进训练。回测至少要和“延续上期”“同期持平”或季节基线比一比。回测结果必须同时报两类误差：MAE 这类绝对误差说明偏了多少，带正负号的平均误差或残差方向说明是不是在系统性高估或低估；不能只报 MAE、MAPE 就结束。方法怎么选，细节见[预测与情景方法](references/forecast-scenario-methods.md)。

## 设计情景和敏感性

基准、乐观、悲观情景必须采用一组内部一致的假设，不是把所有参数一起随手加减 10%。先想清哪些变量是联动的，别在需求下降的情景里，同时假设价格、转化和留存都在变好。

完整测算时，用同一组驱动比较基准、悲观和乐观情景：基准写最可能的路径，悲观写风险会怎么一起发生，乐观写哪些有证据的改善能同时成立。每一行写出驱动值、变化依据和触发条件。用户只质疑某一项时，只改这一项，驱动口径保持和其他情景可比，不必铺开用户没要的整张情景表。

单因素敏感性用来找结果对哪个参数最敏感；双因素表用来看关键组合；目标反推用来算：要达到收入、利润、增长或服务水平，转化、价格、客户数或产能至少要到多少。反推结果不合理时，直接指出是目标和约束相互冲突。

## 给出决策边界

交付驱动等式、输入假设、回测表现、情景结果、最敏感变量和决策阈值。预测写成区间或情景，不伪装成承诺；涉及高风险金融、医疗或重大投资的决策，标明需要专业复核。

只有实际运行模型并复算结果后，才能说测算完成。没有数据时，可以交付空白模型、所需字段和可讨论的假设范围，但不能给出伪造的预测。常见驱动等式和最低验证见[预测与情景方法](references/forecast-scenario-methods.md)。解释已经发生的经营偏差，用“经营差异分析”，不要让面向未来的模型替代历史归因。
