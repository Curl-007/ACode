# 清洗示例：订单导出

用户请求：“按订单号去重，处理支付日期缺失，并说明每步影响多少行。”

正确过程不是立即删除重复：

1. 实际检查 `order_id` 与商品字段，确认一行是一张订单还是一件商品。
2. 将完全相同的重复行与同订单号不同状态的冲突行分开。
3. 对支付日期缺失按订单状态分类：取消订单可能不适用，已支付订单则是质量问题。
4. 先生成变更预览，经规则确认后再输出副本。

示例变更表可写：

| 规则 | 动作 | 命中 | 说明 |
|---|---|---:|---|
| R01 | 去除完全相同的重复行 | 12 | 保留原行号最小的一条 |
| R02 | 标记已支付但无支付日期 | 5 | 不填补，进入待确认清单 |
| R03 | 统一日期格式 | 963 | 20 条不适用，5 条缺失，12 条重复在 R01 移除 |

对账：输入 1,000 行 = 输出 988 行 + R01 删除 12 行。若输入金额与输出金额差额不能由 12 行重复金额解释，清洗状态为未通过。

数字仅用于展示交付结构；未对用户文件实际运行时不得复用为结果。
