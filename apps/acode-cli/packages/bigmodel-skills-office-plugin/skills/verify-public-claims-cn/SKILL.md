# 公开信息事实核查

核验的是一条可判定的声明，不是围绕主题写一篇背景文章。

## 原子化待核验声明

把复合说法拆成主体、动作、对象、时间、地点、数量和限定条件。先写清什么证据能证实或推翻这条声明，别在搜索半路改标准。

用户只给主题、截图或不可判定的表述时，先提炼一条暂定的原子声明，列出还缺哪些限定；能安全核验的部分先做，只有主体或时间完全认不出来时，再让用户补最少的必要信息。多条声明逐条编号，不用整篇背景替代判定。

批量核验时先排序：会不会改变用户决策、有没有传播或合规风险、原始证据拿不拿得到。优先核验高影响且能判定的声明，再处理背景性或低影响声明；来源链相同的声明可以合并取证，但判定仍要逐条给。用户给了时间或条数预算时，先说明覆盖范围；预算用完，剩余项保留为“未核验”，不得把“未发现反证”写成证实，也不得为了凑数降低证据标准。

追到最早的可核验出处：法规原文、数据库记录、公告、完整讲话、论文、原图或原视频。搜索结果摘要、截图、转述和“多家媒体报道”都不是原始证据。引用数字时核对单位、分母、统计期和修订版本。

搜索摘要只用于定位原文。官方 URL 已知或能确定时，直接读原文，不必先搜索。URL 未知时先搜索；搜索命中后，下一步只调用网页读取或其他原文工具，两次工具调用之间不向用户输出任何文字。完成原文读取和判定后再一次性交付结果。

## 排除常见误导

检查旧闻新发、标题夸大、条件省略、相关当因果、累计值冒充当期值、名义值与实际值混用、图片裁切和同名主体混淆。来源互相引用的，算同一条证据链，不算交叉验证。

使用四类结论：证实、错误、误导、证据不足。证据不足时不强行二选一。任何失败返回都只代表“原文内容未取得”，不得引用、翻译、概括或解释失败返回本身。来源获取失败时固定写成“核验结论：证据不足。当前未取得〔原文名称或 URL〕的可读内容，因此无法判定〔声明〕；原文恢复可访问后重试。”除来源 URL、访问日期和结论影响外，不得增加失败技术细节；禁止出现工具名称、“工具”“调用”“读取失败”、服务名称、余额、资源包、错误码、HTTP 状态或调用次数。发送前若草稿含这些词，删除失败解释并改写为上述固定业务口径。

按声明类型选原始来源：统计数字找统计表与方法说明，法规找发布机关原文与生效版本，公司事实找公告/交易所/工商资料，引语找完整录音录像或逐字稿，图片视频找原始文件与时间地点。工具失效就换独立的正式存档；读不到原文，就维持证据不足的判定。

如果核验对象同时涉及组织内部事实，先确认当前会话获准读取哪些内部材料，再按事实类型选择合同、审批记录、业务台账、系统日志或负责人书面确认。内部材料只能证明授权范围内的事实；公开声明该有的公开原始来源，不能拿内部材料替代。交付时分开标注“公开证据”和“内部证据”，不泄露无关客户、员工或交易信息。内部信源不可用时保留待核验项，不得用公开信息猜测内部状态。

公开材料含个人信息时，只保留核验声明所必需的公开职业身份、公开言论和与事件直接相关的字段；私人联系方式、证件、住址、家庭关系、未经证实的敏感画像和无关当事人信息不得摘录或扩散。截图、图片和视频里的个人身份，不是判定必需的，应打码、用代称或省略；“公开可见”不等于可以到处复制。

交付逐项结论、原始声明、关键证据、推理、来源链接、核验时间和剩余不确定性。简单声明使用一张核验卡，复杂任务再附证据链。还在发展中的事件，写明“截至”时间。核验卡见[公开事实核验规则](references/method.md)。
