# 用户行为与产品分析

把用户放回同一条旅程、同一个同期群里，判断谁在哪个环节没有获得价值，产品改动是不是真的改善了用户行为。

## 从价值行为定义用户旅程

先确定研究对象和关键事件：用户从哪里进来，什么行为代表首次获得价值，什么行为代表持续获得价值。登录、页面浏览和点击本身不等于有效使用；观察窗口是日、周还是月，按产品的使用频率来定。

画出最短的关键路径，只留会改变产品决策的环节。漏斗各步必须属于同一批用户、同一观察窗口，且按用户去重；如果步骤会回退、跨设备或重复发生，先把顺序和归因规则定清楚。

用户没给完整事件表时，先把事件—身份—窗口—分母这四项定义交出来，再给能做的描述性判断，不要停在“请补数据”。数据平台或查询工具不可用时，给出能执行的查询逻辑、样例字段和验证方法，不编造曲线。事件级明细只取必要字段，用户标识优先哈希或聚合；位置、通讯录、设备标识等敏感字段须有授权和明确用途。

## 分析留存与用户差异

用起始行为建同期群，用再次发生的价值行为算留存。报告时写清同期群起始人数、观察完整度和各留存期的有效样本量；还没走完整个窗口的新同期群，不能直接和成熟同期群比。

三种分群里挑对行动最有用的一种：来源或角色说明“谁不同”，首次体验说明“从哪里开始不同”，持续行为说明“怎样使用不同”。不要拿结果发生之后的行为去定义人群，再反过来说这个行为导致了结果，这会带来幸存者偏差和信息泄漏。

身份和频率要跟着产品形态走：企业产品优先看组织/席位和角色，消费产品先定账号/设备的合并规则，低频产品用更长的价值窗口；不能默认所有产品都看 DAU 和次日留存。

路径、漏斗和留存的关键判断见[用户行为分析](references/user-behavior-analysis.md)。

## 评估功能和实验

功能渗透率的分母必须限定为有资格使用该功能的用户，不能拿全体注册用户去稀释或夸大结果。比较上线前后的变化，先排除流量构成、季节、事故、投放和埋点变更；没有对照组时只能给相关性证据。

A/B 实验先查分流单位、样本比例异常、跨组污染、运行时长和提前停止，再报告主指标差异、置信区间或效应量，以及体验、稳定性或收入这些护栏指标。实验显著但效应太小，可能不值得上线；不显著也不等于两个方案完全一样。

## 给出产品决策

输出不是一份通用数据报告，而是产品判断：问题集中在哪类用户、旅程哪一步或哪个同期群；这个判断有什么证据支持；接下来是改产品、补埋点、延长实验还是继续观察；改完之后用哪个行为信号验证。

数据不完整时，可以给事件设计、查询思路和最小补数清单，但不得捏造留存曲线或实验结果。经营金额的变化交给“经营差异分析”；指标定义的争议交给“业务指标体系设计”。
