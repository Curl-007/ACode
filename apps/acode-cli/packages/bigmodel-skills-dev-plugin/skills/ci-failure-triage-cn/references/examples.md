# CI 失败原因定位完整示例

## 示例一：材料完整

**用户请求**：“这条流水线红了，找第一个因果失败，不要只列最后的报错。”

**处理**：以下仅说明如何锁定一次可定位到提交与运行编号的流水线失败并组织运行与提交身份和首个因果失败；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：下游几十个失败不能掩盖最早的编译或环境错误。



## 示例二：材料缺失

**用户请求**：“判断这个测试是产品回归还是偶发用例，并给最小复现。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 流水线链接或完整日志；2. 提交差异和基线运行。当前已完成：运行与提交身份框架。待确认：单次重跑成功只能标记疑似偶发，不能证明没有缺陷。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线运行与提交身份。限制：默认只读流水线与日志。下一步：在沙箱或获批环境补一次验证。
