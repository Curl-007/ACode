# 系统性能瓶颈定位完整示例

## 示例一：材料完整

**用户请求**：“定位订单接口 P99 从 300 毫秒升到 2 秒的主导瓶颈。”

**处理**：以下仅说明如何锁定特定版本、负载和环境下的性能退化并组织基线与最小负载／复现条件和HAR／trace／profile 的时间资源分解；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：平均值不能替代 P95、P99 和尾部失败分布。



## 示例二：材料缺失

**用户请求**：“用堆快照验证定时任务内存持续增长的原因。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 基线与当前指标；2. 可重复请求或工作负载。当前已完成：基线与最小负载／复现条件框架。待确认：CPU 高或慢查询相关不等于它是主导根因。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线基线与最小负载／复现条件。限制：压测默认只在隔离环境。下一步：在沙箱或获批环境补一次验证。
