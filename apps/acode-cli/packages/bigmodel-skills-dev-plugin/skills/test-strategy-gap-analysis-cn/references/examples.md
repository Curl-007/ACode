# 测试覆盖与风险分析完整示例

## 示例一：材料完整

**用户请求**：“这次重构覆盖率没降，检查哪些关键行为其实没有测试保护。”

**处理**：以下仅说明如何锁定一次版本变更或系统能力的风险保护网并组织风险到测试矩阵和现有保护证据；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：行覆盖率高不能证明关键行为受保护。



## 示例二：材料缺失

**用户请求**：“为支付重试与幂等设计分层测试策略。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 行为需求与主要失败路径；2. 代码或架构变更范围。当前已完成：风险到测试矩阵框架。待确认：风险严重度 = 影响一至五 × 发生可能一至五 × 当前不可探测性一至五；七十五以上 P0、三十以上 P1、其余 P2。安全、合规、不可逆数据损坏或无法恢复且影响为五时最低 P1，并标记“特殊风险”；风险已发生或正在发生且影响为五时直接 P0。排序固定为风险等级、特殊风险标志、严重度分、最后才是实现成本或替代测试；成本永不降低或跨越风险等级。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线风险到测试矩阵。限制：不在生产环境制造破坏性故障。下一步：在沙箱或获批环境补一次验证。
