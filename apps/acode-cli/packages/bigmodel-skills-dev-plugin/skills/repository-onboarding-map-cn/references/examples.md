# 代码库结构与运行指南完整示例

## 示例一：材料完整

**用户请求**：“我明天接手这个仓库，画出请求入口、核心模块、数据库和测试路径。”

**处理**：以下仅说明如何锁定一个有明确版本的代码库及其运行边界并组织仓库版本与范围和入口到依赖地图；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：文件名只能形成假设，真实入口须由引用关系、脚本解析或运行证据确认。



## 示例二：材料缺失

**用户请求**：“找出订单导出的真实入口和首次安全修改要跑哪些命令。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 仓库路径与当前提交；2. 目标业务能力或接手范围。当前已完成：仓库版本与范围框架。待确认：生成文件、缓存、构建产物和供应商目录不得当作核心源码。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线仓库版本与范围。限制：默认不安装依赖、不启动外部服务、不修改源码。下一步：在沙箱或获批环境补一次验证。
