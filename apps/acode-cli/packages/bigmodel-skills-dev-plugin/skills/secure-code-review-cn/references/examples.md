# 安全代码审查完整示例

## 示例一：材料完整

**用户请求**：“安全审查这个文件下载接口，重点看路径穿越和跨租户。”

**处理**：以下仅说明如何锁定具体代码版本中的可触发攻击路径并组织威胁范围与信任边界和可利用发现与代码位置；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：发现危险函数不等于存在漏洞，必须证明可控数据能到达。

## 可复制的领域成品

> 以下为虚构 OAuth 客户端的格式样板，不代表当前仓库已核验。

### 范围与当前链路
| 项目 | 当前实现证据 | 状态 |
|---|---|---|
| 响应入口 | src/oauth/client.ts:42 读取 authorization_url | 虚构示例 |
| 导航调用 | src/ui/connect.tsx:88 location.assign(url) | 虚构示例 |
| issuer/endpoint/redirect/state/PKCE 绑定 | 当前调用链未发现 | 条件性缺口 |
| 上游响应是否可被攻击者控制 | 上游服务不可见 | 未验证 |

### 当前实现观测与严重度
在隔离测试中用 navigation spy 注入 https://login.example.invalid/authorize；若当前代码直接调用导航，记录“本层接受任意 HTTPS URL”。这只证明本层缺少绑定；上游可控性未证实时定为条件性中危、CWE-601 近似映射，不写成已利用 OAuth 混淆。

### 修复接入点
在解析服务端响应后、任何 location.assign/open 调用前接入 validateAuthorizationResponse；固定 configuredIssuer 和注册 redirect URI，不从响应自举信任根；state 一次消费，code_challenge_method 只允许 S256。

### 同一调用链复测
| 用例 | 当前实现预期 | 修复后预期 | 证据 |
|---|---|---|---|
| discovery issuer 替换 | 记录是否到达导航 | 导航前拒绝 | test oauth-binding #1 |
| authorization_endpoint origin 替换 | 同上 | 导航前拒绝 | #2 |
| redirect URI 不精确匹配 | 同上 | 导航前拒绝 | #3 |
| state 重放 | 同上 | 第二次拒绝 | #4 |
| PKCE plain／缺失 | 同上 | 导航前拒绝 | #5 |
| 合法 issuer + S256 | 记录基线 | 保持成功 | #6 |

只有修复代码已接入真实调用链且 #1—#6 实际运行后，才能写“修复已验证”。独立 validator harness 通过时只写“验收 oracle 已验证；应用接入待验证”。


## 示例二：材料缺失

**用户请求**：“验证这次 SQL 注入修复是否覆盖排序字段和批量查询。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 变更差异与相关调用链；2. 部署配置和信任边界。当前已完成：威胁范围与信任边界框架。待确认：认证成功不代表具备资源级授权；开放重定向、OAuth issuer 混淆和服务端请求伪造必须按实际数据流分别判断。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线威胁范围与信任边界。限制：只在授权代码和测试环境验证。下一步：在沙箱或获批环境补一次验证。
