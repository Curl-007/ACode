# 授权知识答复方法

## 答案分级

- 确定答案：来源有效、适用条件满足、账户事实已确认，可直接答复。
- 条件答案：规则明确但客户条件未知，分别写出条件与对应结论。
- 受阻答案：缺少正式规则、权限或实时状态，只回答已确认部分并发起最小核验。
- 不可提供：涉及绕过权限、披露他人数据或未经授权的价格承诺，明确拒绝并给合规路径。

## 冲突判定

记录来源名称、版本、生效日、适用产品、渠道与冲突字段。正式政策优先于知识摘要；实时账户事实优先于历史工单；任何来源都不能超出其适用范围。仍无法判定时保留冲突，不合并文本。

“A 角色最多 180 天”不能推出“B 角色也最多 180 天”或“所有角色都不能导出全部历史”；适用对象不同就是证据缺口。缺规则找知识负责人，缺客户条件才向客户索取最小条件，两者不能混用。

## 发送前抽查

随机挑答复中三个可证实声明，逐一定位依据。检查客户照步骤操作后能否看见明确成功状态；检查是否索取了不必要的敏感信息；检查是否把内部责任判断写进对外消息。

## 两层答复模板

对外：`结论（含适用条件）→ 必要步骤 → 成功标志 → 限制/下一步`。

内部依据：`产品/租户/套餐/角色 → 来源名称与版本 → 实时账户事实 → 冲突与未确认项 → 核验责任人和反馈时间`。系统不可用时明确哪项实时事实未取得，未获承诺的时间写“待确认”。
