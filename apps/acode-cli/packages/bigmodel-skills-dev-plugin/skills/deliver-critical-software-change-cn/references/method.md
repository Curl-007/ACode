# 关键软件变更检查

验收至少覆盖主行为、一个边界、一个失败路径和权限或兼容。修复必须有能重现原始症状的回归测试；重构应证明外部行为不变。

发布前检查数据迁移、幂等、并发、可观测性、开关和回滚触发。验证证据必须来自当前修改后的完整命令，不引用旧结果。

## 变更包必须回答

- 行为：谁在什么条件下得到什么新结果？
- 所有权：哪一层拥有规则，为什么修改在这里？
- 兼容：旧客户端、旧数据和滚动发布期间发生什么？
- 数据：迁移能否重复执行、如何校验、失败后如何继续？
- 观测：怎样判断上线有效、怎样发现副作用？
- 恢复：触发条件、操作步骤、数据影响和负责人是什么？

“测试通过”必须附当前命令和结果范围；未运行的端到端、迁移演练或生产验证明确列为未验证。
