# 测试覆盖与风险分析

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “这次重构覆盖率没降，检查哪些关键行为其实没有测试保护。”
- “为支付重试与幂等设计分层测试策略。”
- “根据过去三次事故和当前测试列出最高优先级缺口。”

本能力处理的是**一次版本变更或系统能力的风险保护网**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 行为需求与主要失败路径
- 代码或架构变更范围
- 现有测试、事故和生产观测

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 列出会影响用户、数据、安全和恢复的可观察风险
2. 把每个风险映射到成本最低且能发现它的测试层级
3. 检查关键边界、故障注入、并发、兼容和回滚是否有断言
4. 按发生可能、影响、可探测性和维护成本排序补测计划

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 行覆盖率高不能证明关键行为受保护
- 风险严重度 = 影响一至五 × 发生可能一至五 × 当前不可探测性一至五；七十五以上 P0、三十以上 P1、其余 P2。安全、合规、不可逆数据损坏或无法恢复且影响为五时最低 P1，并标记“特殊风险”；风险已发生或正在发生且影响为五时直接 P0。排序固定为风险等级、特殊风险标志、严重度分、最后才是实现成本或替代测试；成本永不降低或跨越风险等级
- 不稳定端到端用例应下沉可确定断言而非简单重试；没有可观察失败信号的需求先补可测性

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 风险到测试矩阵
- 现有保护证据
- P0至P2缺口
- 建议测试层级与断言
- 执行顺序和退出标准

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 不在生产环境制造破坏性故障
- 测试数据不得含真实隐私和凭证
- 不以数量指标替代风险判断
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕一次版本变更或系统能力的风险保护网完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要行为需求与主要失败路径、代码或架构变更范围、现有测试、事故和生产观测中的一项；否则只能交付空白框架和最小补充清单。

超出范围：具体故障用 CI 分诊或故障定位；代码实现用测试驱动实现；浏览器现场结果用旅程验收。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
