# 生产发布与回滚方案

命令退出码为 0 不等于发布成功。成功的标准是：目标行为在真实流量下正确，风险在可接受范围内，而且仍能撤销。

## 按可逆性和爆炸半径定级

先确认变更对象、范围、依赖、客户影响、数据影响、时间窗口、负责人和审批。风险分级看可逆性、爆炸半径、数据迁移、权限与安全、历史稳定性这五项；高风险变更不能因为“只是改配置”就把风险等级降下来。

关键信息不全时，先输出“不可执行项、暂定只读检查、必须确认的对象/版本/环境/审批”，不生成可直接运行的危险命令。

## 把停止条件写进发布计划

发布计划要写清前置检查、分批策略、每批规模、停留时间、观测信号、继续条件、停止条件和回滚方案。数据库变更优先按扩展—迁移—收缩推进，兼容新旧版本；备份必须验证过确实能恢复。开关要写明默认值、权限、清理日期和故障状态。

## 带着触发条件跑灰度

执行前确认制品、提交、环境和审批一致。灰度期间同时看用户关键路径、错误、延迟、容量、业务数据和数据完整性。异常一达到触发条件就立即停止或回滚，不能临场给阈值换个解释。

CI/CD、发布脚本或基础设施自动化失败时，先停在当前批次，查清是否有部分变更、锁或迁移已生效，再按预先写好的回滚方案或前向修复处理；不得绕过闸门手工补跑未知步骤。工具用不了就只交付发布计划和人工核对表，不能声称已经发布。

## 按原验收路径验证发布结果

发布后按原验收路径验证，记录每批的时间、版本、结果和偏差。发布记录、日志和验证样本只保留必要的业务标识并脱敏，不把令牌、完整个人数据或生产机密复制进报告。交付变更记录、执行证据、回滚状态和后续清理项。闸门见[生产发布检查](references/method.md)。
