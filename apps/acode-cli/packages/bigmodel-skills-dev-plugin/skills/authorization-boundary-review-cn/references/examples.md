# 系统权限与越权风险审查完整示例

## 示例一：材料完整

**用户请求**：“审查订单导出是否可能让普通成员看到其他部门数据。”

**处理**：以下仅说明如何锁定系统的资源级访问控制与租户隔离边界并组织授权模型与默认规则和主体资源动作矩阵；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：前端隐藏按钮不能作为授权控制。



## 示例二：材料缺失

**用户请求**：“为项目空间设计角色、对象、动作和数据范围授权矩阵。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 角色、资源和业务规则；2. 服务端路由与数据访问代码。当前已完成：授权模型与默认规则框架。待确认：角色允许某动作仍需检查具体资源与租户范围。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线授权模型与默认规则。限制：不使用他人真实账号测试越权。下一步：在沙箱或获批环境补一次验证。
