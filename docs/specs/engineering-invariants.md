# 工程不变量(开发规则)

## 定位

本文件承载 ACode 仓库的**跨切面工程不变量**:多个互不相关子系统的事故复盘里反复独立出现、
但尚未被仓库现有治理集中表述的规则。来源是一份外部通用规则集(155 条),对照当前检出逐条
裁剪而来。

- **性质**:面向**在本仓库工作的开发者与 AI 会话**的开发规则。不是产品运行时送给模型的
  提示词——那一面归 `apps/acode-cli/specs/prompt-language-policy.md`(恒英文)与各提示词
  spec,与本文档是两个面。
- **只做增量承载**:与现有治理(两份 `AGENTS.md`、`DESIGN.md`、`architecture-policy.yaml`、
  `.agents/skills/`、各包 `specs/`)重叠的规则**不在此复制**,而是在「指针索引」节指向
  单一真源。这是本文件自己第 EI-2 条(一个语义一份实现)的要求:复制即制造第二真源,
  两份必发散。
- **优先级**:与 `AGENTS.md`、`architecture-policy.yaml`、`DESIGN.md` 冲突时,**以那些文件
  为准**;本文件只在它们沉默处补充。冲突点已在下节显式登记。

## 冲突裁决记录

以下 7 处是外部规则集与本仓库现状的直接张力,裁决写死,防止后人把本文件当第二真源:

1. **文件/函数行数上限**:外部规则给 800/50 行。本仓库以 `architecture-policy.yaml` 为准
   (`maxFileLines: 400`、`maxContractLines: 300`、`maxPublicMethods: 12`),并由
   `pnpm architecture:check` 机器化执法。本文件**不复制任何数字**(复制即漂移)。
2. **UI 设计 token 纪律**:颜色/字号/间距/圆角/尺寸全部以 `DESIGN.md` 为准。本文件只补
   DESIGN.md 未覆盖的**动效行为增量**(见 EI-UI 节),不重述 token 规则。
3. **安全与隐私**:密钥处理、日志脱敏、遥测、信任分级、凭据同步等以对应安全 spec 为准
   (见指针索引「安全」组)。本文件只保留框架级铁律(绕过服务层默认禁止、确认框默认指向
   安全方向)。
4. **"新存储优先文件而非数据库"**:保留为 EI-42,但注明 session 模块直连 `node:sqlite` 是
   `architecture-policy.yaml` 已登记的既成形态(policy 注释:"55 处 node: 导入含 node:sqlite
   直连"),不是本规则的违例。
5. **验证分层**:外部规则要求"单测过≠集成过≠实机过≠生产过,各层证据独立记账"。产品 CLI 侧
   的自验证学说在 `apps/acode-cli/specs/verification-doctrine-prompt.md`(那是**运行时提示词**);
   本文件保留的是**开发者如何验证改动**的纪律(EI-8),两者不同面、不重复。
6. **UI 交互行为**:`DESIGN.md` 只覆盖**视觉**。反馈时长分级、通道判定、toast 边界、空态、
   主动打扰闸门、破坏性操作措辞、长列表分组等**交互行为**是真空,由本文件 EI-UI 节承载。
7. **协作派工**:外部规则谈"开发者/AI 如何拆派 ACode 的开发工作"(宽/深任务、契约冻结、
   规格自足、非作者评审)。产品 CLI 侧 `apps/acode-cli/specs/dispatch-discipline-prompt.md`
   谈的是**运行时模型如何派发子代理**,是不同面。本文件 EI-13 节承载开发协作面。

## 规则正文

编号沿用外部规则集原始序号(EI-n = 源第 n 条),便于回溯;合并项在括号内标出。

### 一、铁律(跨领域不变量)

- **EI-1 禁止静默降级**。任何功能回退、替换、失败兜底必须让调用方/用户可见。悄悄换行为的
  事故最终都靠用户抱怨发现,排查成本远高于当初加一个状态提示。
- **EI-2 一个语义只允许一份实现**。解析、校验、白名单、常量、主题值必须有单一事实源。第二份
  实现出现的那一刻两份就开始发散,"修一处漏其他"从此成为常态。(本文件的指针策略即此条的
  应用。)
- **EI-4 fail-closed / fail-open 必须显式决定并写下来**。破坏性与安全判定默认 fail-closed
  (不确定就不做);兼容与可用路径默认 fail-open(解析不了保持旧行为)。最危险的不是选错方向,
  而是没做选择、靠运行时偶然行为决定。
- **EI-6 一切资源必须有界**。队列、缓冲、缓存、连接池、并发数、重试次数、注入预算全部有上限
  和明确溢出策略。无界资源上线第一天不出事,流量高峰那天出事。
- **EI-7 关键写入必须原子,迁移必须幂等**。临时文件 + 同步落盘 + 重命名是配置/状态文件默认
  写法;迁移可重复执行、不覆盖用户手工修改、单向进行。崩溃在写一半的时刻,截断的配置会让下次
  启动丢关键数据。
- **EI-8 验证发生在真实边界,证据分层记账**(合并源 113)。单测过 ≠ 集成过 ≠ 目标平台实机过
  ≠ 生产过;各层证据独立记录、不能互相替代,目标平台行为必须在目标平台验证。人工验收项不得用
  自动化冒充,自动化覆盖不了的部分如实标注未验证。(与 `AGENTS.md`「验证」节、
  `docs/specs/cli-validation-gates.md` 同源,本条是"分层不互替"这一元规则。)
- **EI-9 能力声明必须诚实**。未落地的能力不宣传;数据未知就显示"未知",不用编造默认值假装
  精确。一个看似精确但分母错误的数字比空白更有害——它剥夺了用户怀疑的机会。
- **EI-10 环境隔离,改什么就部署什么再测什么**(合并源 72)。dev 与生产的数据、端口、标识、
  协议前缀、窗口标题完全隔离,两实例并行是常态;修改共享库后必须重建并重部署所有依赖进程。
  "界面是新的、行为是旧的"(测试跑在旧二进制上)是最难排查的幽灵 bug。

### 二、失败处理与降级

- **EI-11 区分"明确未执行"与"执行状态未知"**。连接拒绝/校验失败/不存在 = 明确未执行,可安全
  重试;超时/连接重置/响应丢失 = 状态未知,对有副作用的操作**禁止自动重放**,必须报告"结果
  不确定"。
- **EI-12 有副作用的操作默认 at-most-once**,除非全链路实现幂等(幂等键 + 服务端去重)。
- **EI-14 写操作遇歧义(目标/环境不明)时失败并要求显式指定**,绝不静默替用户选一个执行。
- **EI-16 重试必有上限和退避**;达上限后进入可见终态(告警 + 人工介入入口),不无限重试、不
  静默停摆。
- **EI-17 降级形态在设计功能时一并设计**,不是事故后补。降级文案用中性语言描述**保留了什么**
  ("当前环境不支持 X,已保留 Y"),不描述为错误,也不用无法验收的形容词。
- **EI-18 失败要有账本 + 熔断 + 人工复位**。连续失败达阈值停止自动动作;失败计数跨重试结转、
  不因重试归零;纯内存态的失败记录会随进程规模静默腐坏。

### 三、契约、接口与边界

- **EI-21 跨边界事件两侧都要有穷举测试**(发送端每个非默认分支 + 接收端每个分发分支),否则
  新增事件会在某处被静默丢弃而无人知晓。
- **EI-22 唯一性约束落在存储层**(唯一索引/事务),不靠生成端约定——约定总会被第二个写入者
  打破;无限制条件的批量更新会覆写不该覆写的行。
- **EI-25 字段命名与格式约定全项目统一**;空值用显式 `null` 表达,不靠字段缺失表达状态。
- **EI-26 时间序列数据落有界桶或事件流**,不指望从单个 `lastXxxAt` 字段反推历史。

### 四、生命周期与资源管理

- **EI-28 判定资源(进程/会话/任务)终止的唯一权威证据是所有者的显式终态事件**;不从旁路信号
  (钩子上报、日志、轮询超时)推断终止——旁路信号代表状态变化,不代表生命结束。
  (先例:`packages/services/specs/task-index-write-ownership.md`、
  `apps/acode-cli/specs/subagent-terminal-first-wins.md`。)
- **EI-29 终止事件先于状态移除发出**,或走可靠通道兜底。"移除状态→再发事件"的空窗在轮询/
  竞态下必然丢消息(资源死了,界面永远不知道)。
- **EI-30 销毁覆盖所有路径**:单个关闭、批量关闭、父容器销毁、整体替换、后端驱动全部走同一条
  销毁管线;部分路径可跳过确认,但绝不跳过回收。
- **EI-34 破坏性操作(kill/删除/覆盖)执行前一刻重新校验目标身份**(PID、版本、归属),防
  TOCTOU:快照与执行之间永远有窗口,标识符会被系统复用。
- **EI-35 "写入自动化、删除手动化"的单向流必须设计时定死回收机制**(TTL、活性判死、定期对账),
  否则死数据只增不减。
- **EI-36 清理操作默认只删记录不删数据**(软删/归档),文案显式声明"不删除磁盘上的任何文件";
  级联硬删只留给显式的、二次确认的入口。
- **EI-37 存在性判定是三态**(存在/不存在/无法验证):远程路径、未挂载卷、权限不足判"无法
  验证";清理/删除对话框对无法验证项默认**不勾选**——误删比残留贵得多。
- **EI-39 事件回调快进快出**:钩子/回调线程只做提交与转发,耗时处理进后台队列;禁止在事件
  回调里做网络 IO 或重计算。

### 五、数据与持久化

- **EI-40 原子写三部曲**:写临时文件 → 强制落盘 → 重命名;关键文件写前留备份。内存快照在磁盘
  写成功后才替换(clone → 改 → 写盘 → 换快照),失败时内存与磁盘都保持旧值。
- **EI-41 迁移幂等**:同一数据重复执行无副作用;用户手工编辑过的文件不覆盖;保留旧数据不自动
  删除;写迁移日志。迁移误改的数据要有同样幂等的修复路径。
- **EI-42 Schema 版本用正规机制**(版本表/pragmas),不靠捕获"列已存在"类错误字符串判幂等——
  数据库换版本时错误文案会变,判断会静默退化成硬失败。
- **EI-46 需要进 WHERE 过滤或索引的字段用独立列**,不塞进 JSON 元数据字段(无法索引、无法
  高效过滤)。
- **EI-47 持久化设置必须有默认值、非法值归一化、旧版本覆盖路径**;缺失字段不得导致崩溃或
  不可用状态。
- **EI-48 真实源与派生索引分离**:索引可随时从真实源重建;高频易变字段(访问计数、最后使用
  时间)只进索引不进真实源——否则每次读取都污染内容历史/diff。
- **EI-49 新子系统存储优先文件(JSON/JSONL)而非新增数据库迁移**,除非确需关系查询——零迁移
  成本是真实收益。**豁免**:session 模块直连 `node:sqlite` 是 `architecture-policy.yaml` 已登记
  的既成形态(冲突裁决记录第 4 点)。
- **EI-51 文件库类存储默认内容寻址**(按 hash 去重)+ 存相对路径(跨机器可移植)。
- **EI-52 用户数据的删除权与恢复路径同时设计**:默认归档,"彻底删除"是显式动作;删除前先给
  当前状态拍快照。

### 六、并发与异步

- **EI-54 通知型原语(watch/observable)只在值实际变化时通知**;检查"清空/消费"操作是否会再次
  发布通知——无条件通知 + 监听器再清空源 = 自唤醒环,烧满一个核。
- **EI-55 通道关闭/发送端丢弃的错误必须终结循环**(return/break),不能只 continue——关闭后的
  等待会立即返回错误,形成忙等环。
- **EI-56 合批窗口的截止时间从首个数据到达时起算且不可后延**。"收到新数据就重置计时器"会让
  持续小流量下的转发延迟无界增长(实测毫秒级劣化到数百毫秒)。
- **EI-57 流控/信用记账点设在"处理完成"而非"收到/入队"**;瞬时 ACK 背后是下游无界队列。记账
  用字节量纲不用消息条数——条数无法预测内存。
- **EI-59 用世代号(generation)防旧请求覆盖新状态**:异步响应带世代,旧世代响应到达即丢弃;
  轮询请求防重入。
- **EI-61 去抖与节流不得吞掉语义事件**:合并"尺寸变了"可以,合并"删除了""退出了"就是永久丢
  语义——事件可否合并由**语义**决定,不由频率决定。
- **EI-62 判断"循环是不是自旋"看每条路径是否都有 await/阻塞点**,不看循环形态;反之每个"永久
  ready"的等待都是隐性自旋。
- **EI-63 并发构建共享产物目录会产生与源码对不上的幻影错误**;报错先确认标识符真实存在,再
  串行重跑判断。

### 七、平台与环境差异

- **EI-65 不信任第三方库的静默回退**:库对无效输入的"安全默认行为"(无效工作目录回退 HOME、
  解析失败返回空)在关键路径上是暗雷——自己先做不回退的显式校验,紧邻使用点再校验一道。
- **EI-67 全局环境操作(重启系统/服务、改机器级配置)**:"写入"与"生效"分离,影响面全量列出
  (含产品之外的组件),默认动作是取消;绝不把重启做成保存的副作用。
- **EI-68 读操作不得有写副作用**:读配置文件不应启动服务、唤醒虚拟机、建立网络连接——"查看
  状态"的功能自己改变了状态,就是新问题源。
- **EI-71 测试环境隔离**:测试用 HTTP 客户端禁用系统代理,测试端口随机或专用,测试不依赖宿主机
  真实环境变量——否则本机能过、设了代理的机器全挂。
- **EI-73 固定服务端口必须避开 OS 临时端口分配区间**;端口被占时显式报错并给排查提示,绝不
  静默换随机端口——启动时一次性读配置的客户端会在端口漂移后永久失联。

### 八、安全与隐私

(本节多数条目已由安全 spec 承载,见指针索引;此处只保留框架级铁律。)

- **EI-80 绕过服务层直写数据库/存储的逃生阀默认禁止**;确需开放必须同时满足:精确 schema 校验、
  显式事务、CAS、字段白名单、写后回读校验、专用退出码,且输出明示"已绕过常规不变式"。
- **EI-81 危险操作二次确认 + 影响面明示**;确认框默认按钮指向安全方向(默认"否");静默安装/
  卸载路径一律不删用户数据。

### 九、性能

- **EI-87 资源限制用软限优先**:降优先级/权重配额优于硬顶/OOM kill——硬限制造用户无法归因的
  失败(用户只看到"编译变慢/构建失败",想不到是你设的限);软限验收标准是"正常负载劣化不超 X%"。
- **EI-90 大数据处理分块 + 让出主线程**:块大小按字符/字节设上限,累计处理时间设上限(到点
  让出),切块保留编码边界(不切多字节字符/代理对/转义序列中间)。
- **EI-91 恢复/重放期间保留旧画面,写完一次性交换**;不让用户看着内容从头滚到尾,也不为等待
  交换无限阻塞(设上限,超时降级)。
- **EI-93 昂贵视觉效果(视频/粒子/模糊)有降级决策链**,按序判定(省电模式→无障碍设置→硬件
  能力→电池→解码错误),返回可诊断的 `{mode, reason}`;不可见/失焦/切走时立即暂停。
- **EI-97 数据丢弃要丢得完整**:溢出时整段丢弃并置"失步"标记,走快照重同步恢复;绝不从中间
  截断结构化流(协议序列/编码单元)——截断产生确定性损坏,比丢失更糟。可丢的(中间帧)与不可
  丢的(终止事件、删除语义)分开定策略。

### 十、用户界面与体验(交互行为;视觉归 DESIGN.md)

(冲突裁决记录第 6 点:本节只承载 DESIGN.md 未覆盖的**交互行为**;视觉 token/字号/圆角/
可访问性视觉/响应式见 `DESIGN.md`。)

- **EI-98 反馈按时长分级**:0–100ms 无反馈(任何反馈都像故障闪烁);100ms–1s 仅禁用态;1–3s
  加 spinner;3s 以上或多步动作用阶段文字标签,不许无标签转圈。会切换长文案的按钮事先固定宽度
  (防跳动);可能瞬间完成的操作,loading 延迟约 200ms 再显示(防闪烁)。
- **EI-99 反馈通道用判定矩阵、自上而下命中即停**:阻断流程的告警→横幅(收敛到统一挂载点);
  表单字段错误→就地内联,随修正即时消除;需回看的异步事件→通知中心;其余瞬时确认→toast。
  同一事件只在一个通道提示一次。
- **EI-100 Toast 边界**:结果已在界面可见的同步操作不弹;高频事件(拖拽/光标/流式输出)不弹;
  错误 toast 必须可行动(什么失败 + 原因 + 下一步),"出错了"不如不弹;批量失败聚合成一条;
  持续可见的状态用内联徽章,不用会消失的 toast。
- **EI-101 空态给出路**:图标 + 说明 + 直接获取/配置数据的动作按钮,不用裸文本"暂无数据";
  "搜索无结果"不是空态,简单文本即可;行内小提示不强套插画。
- **EI-105 动效行为增量**(视觉 token 归 DESIGN.md):只动画 `transform`/`opacity`;尊重
  reduced-motion 偏好(减弱而非归零,对接 DESIGN.md 的 `data-acode-reduce-motion` 轴);高频
  键盘入口零动画;**退出快于进入**;不混用框架内置动画与 token 时长体系。
- **EI-107 文案纪律**:不 overclaim(拿到真实结果才用结果动词,进行中用中性过程语);删除填充词;
  展示的快捷键与真实绑定一致(宁可不显示,不显示错的);多语言文案同批提交(对接 `AGENTS.md`
  i18n 与 `apps/acode-cli/specs/prompt-language-policy.md` R5);控件命名表达方向。
- **EI-109 主动打扰(新功能提示/更新卡片/引导)共用一套全局闸门 + 频率纪律**:用户活跃时不打扰、
  启动初期不打扰、已有模态不打扰、每会话限额、"跳过此版本"永不再提、连续忽略则频率减半;闸门
  规则集中写在一处,不做成调用方各自传的布尔。打扰型功能失败只有一种方式:烦人。
- **EI-110 破坏性 UI 操作按"会清空什么"设计与措辞**;引导每步可跳、整体可跳、老用户升级不
  触发;预检缺项给可读的修复卡(一键复制修复命令),不用报错弹窗。
- **EI-111 长列表分组**:短组平铺、长组默认折叠 + 组头计数摘要;搜索只裁剪可见行不改全量计数;
  异步加载的折叠状态不覆盖用户已手动切换的选择。

### 十三、协作与派工(人与人、人与 AI)

- **EI-135 拆分形状先行**:宽任务(多个独立同构子任务)并行扇出;深任务(一条语义贯穿多层)拆
  流水线不拆实现——硬拆深任务只产出接缝 bug;探索任务不拆。
- **EI-136 派工前三关**:验收判据一句话可执行 / 整个报废重做的代价有界(小时级)/ 验收能快速
  完成;任一不过说明缝切歪或粒度太粗。并行度 = 1 是合法且常见的答案,不为并行而并行。
- **EI-137 契约冻结先行**:跨边界接口(数据结构、函数签名、类型、事件、测试骨架)先写成提交再
  派发实现——契约是并行的杠杆,同时把不变式移出并行区,消除语义冲突。(与本仓库 spec-first、
  `architecture-governance` 的 contract.ts 先行同构。)
- **EI-138 派发的任务规格必须自足**:文件路径、原始报错文本、约束、完成的定义;不依赖共享上下文
  或口头意图——跨人/跨模型传递意图是已知故障模式。
- **EI-139 评审由非作者执行**(含不同 AI 模型交叉评审),专治"我审我";语义密度最高的部分(契约

- **EI-140 并行期间每路只跑自己范围内的编译/单测**,全量门禁由主线最后统一跑一轮——否则验证
  时间随路数线性翻倍。
- **EI-141 并行实例的工作通过环境隔离互不干扰**;提交前检查工作区,不认识的改动、不认识的新
  提交必须先弄清来源(它们会随你的提交/标签一起发布)。
- **EI-142 用数据决策不用直觉决策**:砍功能前先落调用计数,零调用者进砍单;疑似伪需求不拍死,
  等数据说话。计数埋点遵守遥测纪律(`apps/acode-cli/specs/no-telemetry.md`)。

### 十四、API 与产品设计决策

- **EI-143 用显式枚举表达"跟随默认/明确指定/明确不要"三态**,不用 `null`/缺失表达"不要"——
  缺失无法区分"没传"与"明确不要",回退逻辑会把"不要"再次填上。
- **EI-144 一切引用用稳定 id 作键**,显示名可自由改名不影响引用;重命名不得使历史数据、收藏、
  外链失效。
- **EI-145 预览与真实执行共用同一套解析逻辑**;预览优先级与执行优先级分叉是设计错误——用户
  看到的必须就是发生的。
- **EI-146 API/工具面克制**:调用方在真实任务里永远不会做的事,不配占用接口面;管理面长尾下沉
  到独立入口;用法教学放文档/skill,不放接口描述——接口 schema 是每次调用的固定上下文成本。
- **EI-147 返回值默认精简**(尾部摘要、去噪),细节按需展开(verbose 参数);schema 是固定成本,
  返回值是累计成本,长会话里后者往往更大。
- **EI-149 逃生阀只能是用户显式配置**(环境变量/配置项,优先级高于默认值),绝不自动回退到
  逃生阀;逃生阀的存在与代价写入文档。(对接 `apps/acode-cli/AGENTS.md` 的 `ACODE_` 环境变量
  纪律:新增前先在 spec 定义用途、优先级、错误行为、测试覆盖。)
- **EI-152 默认值三级**:用户显式选择 > 用户偏好设置 > 硬编码回落;偏好设置读取时校验合法性,
  非法值走回落而不是进入不可用状态;默认逻辑保持纯函数,由调用点注入。
- **EI-154 面向自动化调用方(AI/脚本)的接口**:控制语义用协议可表达的形式(转义序列、枚举),
  不教调用方发协议表达不了的东西;观测语义("这个状态意味着什么、什么时候该停手")收敛到一份
  共享契约,所有调用方回引,不各自复述。
- **EI-155 身份核对前置**:自动化调用方在写操作前必须核对自己的身份标识与所连服务端一致;不一致
  即串台,立即停止一切写操作并上报——注入缺失时系统往往静默回退到共享默认配置,所有调用"正常
  返回"(只是别人的数据),调用方无法自察。(与本仓库 Workspace Identity 纪律同源,见
  `AGENTS.md`「Workspace Identity」节。)
