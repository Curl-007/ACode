# 数据库迁移安全设计完整示例

## 示例一：材料完整

**用户请求**：“给亿级订单表新增非空渠道字段，设计无停机迁移。”

**处理**：以下仅说明如何锁定生产数据库结构或数据语义的可逆变更并组织迁移风险清单和分阶段执行计划；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：回滚应用不等于能回滚已改写的数据。



## 示例二：材料缺失

**用户请求**：“审查这份回填脚本的锁、复制延迟和可恢复性。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 当前和目标 Schema；2. 表规模、写入速率和高峰窗口。当前已完成：迁移风险清单框架。待确认：在线 DDL 能力必须以具体引擎和版本文档为准。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线迁移风险清单。限制：不直接执行生产 DDL 或回填。下一步：在沙箱或获批环境补一次验证。
