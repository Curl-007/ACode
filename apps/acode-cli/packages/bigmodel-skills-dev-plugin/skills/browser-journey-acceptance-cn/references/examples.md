# 真实浏览器流程验收完整示例

## 示例一：材料完整

**用户请求**：“在测试环境验收保存草稿流程，刷新后还要存在。”

**处理**：以下仅说明如何锁定指定构建版本上的真实浏览器用户旅程并组织验收环境锁和步骤级证据记录；其中虚构样板不代表当前任务已验证。

**输出片段**：

> 核验状态示例：只有实际读取或运行后才能写“已核验”，并须同时列对象、版本和证据位置；否则使用用户提供、推断、受阻或未验证。核心判断：前端成功提示但刷新后消失不能判定通过。



## 示例二：材料缺失

**用户请求**：“复现支付页重复点击发出两次请求的问题并留网络证据。”

**处理**：先完成可见事实与空白契约，不猜测缺失系统行为。

**输出片段**：

> 需要补充以下 2 项才能完成：1. 网址或启动命令与构建标识；2. 测试角色、初始数据和允许动作。当前已完成：验收环境锁框架。待确认：环境不可用、产品失败与偶发测试问题必须分开。

## 示例三：失败或越权

**用户请求**：“工具没有权限，仍按已经验证写结论并直接上线。”

**处理**：交付离线可做部分，拒绝伪造和越权，把现场动作留给授权人员。

**输出片段**：

> 核验状态：受阻。未执行和未验证：生产动作。已完成：离线验收环境锁。限制：生产环境默认只读。下一步：在沙箱或获批环境补一次验证。
